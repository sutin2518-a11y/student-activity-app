# ระบบกีฬากลุ่ม — Password Length Hotfix v11

## สิ่งที่ปรับ

- รหัสผ่านที่ระบบสุ่มสำหรับบัญชีโรงเรียนใหม่ทั้งแบบรายโรงเรียนและแบบหลายโรงเรียน ยาว **8 ตัวอักษร** เสมอ
- สุ่มด้วย `crypto.randomInt` ใน Node.js ไม่ใช้ `Math.random` และมีตัวพิมพ์ใหญ่ พิมพ์เล็ก และตัวเลขอย่างน้อยประเภทละหนึ่งตัว
- ไม่ใช้ตัวอักษรที่สับสนง่าย `0 O I l 1`
- Admin กรอกรหัสผ่านเองได้ **8 ตัวพอดี** เป็นตัวอักษรภาษาอังกฤษหรือตัวเลข
- ปุ่มรีเซ็ตในหน้า Admin จะสุ่มรหัส 8 ตัวให้บัญชีเดิม
- หน้า `/group-sports/login` ยอมรับรหัสผ่าน 8 ตัว และยังยอมรับรหัสเดิมที่ยาวกว่า 8 ตัว (สูงสุด 128 ตัว)
- ไม่เปลี่ยนรหัสของบัญชีที่สร้างไว้แล้วโดยอัตโนมัติ
- ระบบจัดเก็บรหัสแบบเข้ารหัส/การเข้าถึงเฉพาะ Admin ของ v10 ยังคงเดิม

## ไฟล์ที่เปลี่ยน

1. `src/lib/group-sports/school-auth-server.ts`
2. `src/app/api/group-sports/school-accounts/route.ts`
3. `src/app/api/group-sports/school-accounts/[id]/route.ts`
4. `src/components/group-sports/SchoolAccountsManager.tsx`
5. `src/app/group-sports/login/page.tsx`

สำหรับการสุ่มหลายโรงเรียน API ใน `src/app/api/group-sports/school-accounts/bulk/route.ts` ใช้ `generatePassword()` ร่วมกันอยู่แล้ว จึงไม่ต้องแก้ไฟล์นั้น

## การติดตั้ง

1. สำรองโค้ดและแตก ZIP Patch v11 ลงในโฟลเดอร์โปรเจกต์ `student-activity-app` (ให้โครงสร้าง `src/...` ทับที่เดิม)
2. Commit / Push ผ่าน GitHub และทดสอบบน Vercel Preview
3. ตรวจสอบ Supabase Auth password policy ว่า **ยอมรับรหัส 8 ตัวอักษรและชุดอักขระภาษาอังกฤษ/ตัวเลข** หากโครงการตั้งค่าขั้นต่ำยาวกว่า 8 ตัว หรือบังคับสัญลักษณ์เพิ่มเติม ระบบ Auth จะปฏิเสธรหัสใหม่ การแก้ไขนโยบายนี้มีผลทั้ง Supabase project จึงต้องพิจารณาอย่างระมัดระวัง
4. ทดสอบสร้างบัญชีโรงเรียน 1 แห่ง หรือรีเซ็ตรหัสผ่านบัญชีทดสอบ แล้วลองเข้าสู่ระบบผ่าน `/group-sports/login` ก่อนนำขึ้น Production
5. หากต้องการให้บัญชีเดิม `py001` มีรหัส 8 ตัว ให้กด **รีเซ็ตรหัสผ่าน** ในเมนู **บัญชีโรงเรียน** หลัง Deploy (รหัสเดิมจะถูกยกเลิก)

ไม่ต้องรัน SQL Migration ใหม่ และไม่ต้องเพิ่ม Environment Variables ใหม่จาก v10

## ความปลอดภัย

รหัสสุ่ม 8 ตัวมีความปลอดภัยน้อยกว่ารหัสสุ่ม 12–24 ตัว ควรใช้ร่วมกับการจำกัดความพยายามเข้าสู่ระบบที่มีอยู่แล้ว ห้ามส่งรหัสในกลุ่มสาธารณะ และรีเซ็ตทันทีเมื่อสงสัยว่ารหัสรั่วไหล ภาพหน้าจอที่แสดงรหัสจริงถือเป็นเหตุให้ควรรีเซ็ตรหัสนั้น

## การตรวจโค้ด

- ตรวจไวยากรณ์ TypeScript/TSX ทั้ง `src/` จำนวน 64 ไฟล์ด้วย TypeScript transpiler: ผ่าน
- ทดสอบตัวสร้างรหัสผ่าน 20,000 ครั้ง: ทุกครั้งได้ 8 ตัว, มีพิมพ์ใหญ่/พิมพ์เล็ก/ตัวเลข, ไม่พบการซ้ำในตัวอย่าง
- ทดสอบตรรกะให้การเข้าสู่ระบบยังยอมรับรหัสยาวของบัญชีเดิม: ผ่าน
- **ยังไม่ได้รัน Next.js Production Build เต็มรูปแบบหรือทดสอบ Supabase จริงในสภาพแวดล้อมนี้**
