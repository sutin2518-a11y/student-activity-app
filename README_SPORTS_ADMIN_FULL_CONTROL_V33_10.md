# ภูลังกาเกมส์ 2569 — v33.10 Admin Full Control

## ขอบเขตงาน

ต่อยอดจากระบบกีฬากลุ่ม v33.9 โดยไม่แก้ไขเวิร์กโฟลว์การรับสมัคร/การประกาศผลตามปกติ:

- โรงเรียนส่งใบสมัครแล้วระบบรับข้อมูลอัตโนมัติ (`approved` = รับข้อมูลแล้ว ไม่ได้หมายถึง Admin ตรวจสอบ)
- กรรมการที่ได้รับมอบหมายกดส่งผลแล้วประกาศทันที ไม่ต้องให้ Admin อนุมัติ
- Admin หลักเปิด **จัดการแข่งขัน → Admin Full Control · แก้ไขทุกใบสมัคร** หรือ `/group-sports/admin`
- ค้นหา/เปิดใบสมัครโรงเรียนใดก็ได้ ทุกประเภท: กีฬาเดี่ยว ทีม กรีฑา ฟุตบอล 4 รุ่น และ RoV
- แก้ชื่อทีม/ใบสมัคร ชื่อนักกีฬา รหัสนักเรียน ชั้น เพศ ตามประเภทกีฬา เพิ่ม/ลบรายชื่อนักกีฬา และเพิ่ม/ลบ/แก้ไขครูผู้ควบคุมและเบอร์โทร
- ฟุตบอล: วันเกิด เบอร์เสื้อ ตำแหน่ง และผู้จัดการทีม ข้อมูลบันทึกในตารางรายละเอียดฟุตบอลเดิม
- RoV: ชื่อในเกม บทบาทในทีม และตำแหน่งในเกม ตรวจจำนวนตัวจริงและสำรองตามข้อกำหนด
- แนบ/เปลี่ยนรูปนักกีฬาผ่าน Bucket ส่วนตัวเดิม โดยหลังเปลี่ยนชื่อ/รหัส/ตำแหน่งของนักกีฬา ต้องแนบรูปใหม่เพราะที่เก็บรูปผูกกับตัวตนและลำดับเดิมเพื่อไม่ให้สลับรูปคน
- การแก้ไขข้อมูลผู้รับเกียรติบัตร: ยกเลิกเอกสารเดิมที่ยังไม่ถูกยกเลิก ออกฉบับใหม่พร้อมเลขที่และ QR ใหม่ใน transaction เดียวกัน และเก็บประวัติใบเดิม/QR เพื่อตรวจสอบย้อนหลัง
- เก็บผู้แก้ เหตุผล วันเวลา Snapshot ก่อน/หลัง และจำนวนเอกสารที่ยกเลิก/ออกใหม่ ทุกการแก้ไข
- ป้องกันบันทึกทับจากอีกเครื่องด้วย `updated_at` และจำกัดการเรียก RPC เฉพาะ `sports_stage3_admin` (Admin หลัก)
- หน้า Admin เชื่อมเมนูจัดการข้อมูลโรงเรียน โปรแกรมฟุตบอล RoV กรรมการ ผลแข่งขัน เกียรติบัตร และรีเซตไปยังเครื่องมือเดิม

## ข้อจำกัดที่ต้องทราบ

**"Admin Full Control" ในรุ่นนี้หมายถึงความสามารถแก้ใบสมัครทุกประเภทจากหน้ากลาง และเข้าใช้เครื่องมือ Admin ของแต่ละส่วนตามสิทธิ์ที่ระบบเดิมรองรับ** ไม่ได้หมายถึงเขียนเครื่องมือใหม่สำหรับแก้ทุกฟิลด์ภายในทุกตารางของระบบทั้งโครงการ ระบบผลสกอร์รายแมตช์ยังแก้ในหน้าเฉพาะกีฬาที่เกี่ยวข้อง และผลอันดับหลังประกาศยังแก้ใน `/group-sports/results/corrections` ตาม v33.9

- ไม่เปลี่ยนโรงเรียนเจ้าของใบสมัครหรือย้ายรายการแข่งขันด้วยการแก้ roster; หากต้องย้ายจริง ต้องตรวจผลและเอกสารอ้างอิงก่อนเป็นกรณีพิเศษ
- ใบสมัครที่ถอนแล้ว (`withdrawn`) ไม่สามารถแก้ผ่านหน้ากลาง
- ไม่แก้ผลการแข่งขัน/อันดับโดยอัตโนมัติเมื่อแก้ชื่อนักกีฬา หรือชื่อใบสมัคร (ผลอันดับยังคงเดิม); ระบบอัปเดตชื่อรายการในตารางผลกีฬาเดี่ยวถ้ามีข้อมูล และออกเกียรติบัตรใหม่เมื่อมีฉบับที่ยังไม่ยกเลิก
- เอกสารเกียรติบัตรเดิมเก็บ Snapshot และ Token เดิมไว้ เพื่อให้ QR เก่าตอบว่า 'ยกเลิกแล้ว' ได้ ผู้ที่ได้รับใหม่ในตำแหน่งเดียวกันอาจไม่มีลิงก์เชื่อมกับเอกสารเก่าหากชื่อเปลี่ยน เพื่อป้องกันเชื่อมเอกสารผิดบุคคล
- การสำรองฐานข้อมูลไม่ได้สำรองไฟล์ภาพใน Supabase Storage ต้องสำรองแยกต่างหาก
- รูปเก่าที่ผูกกับชื่อ/รหัส/ลำดับก่อนเปลี่ยนไม่ถูกลบอัตโนมัติ เพื่อป้องกันสูญหาย; ผู้ดูแลอาจต้องจัดการรูปที่ไม่ใช้ภายหลัง
- ต้องตรวจสอบกติกาคุณสมบัตินักกีฬาที่หน้างานตามระเบียบ แม้ระบบจะรับข้อมูลแล้ว

## วิธีติดตั้ง

1. สำรอง Supabase Database + Storage และ Commit งานจาก GitHub Desktop ก่อน
2. แตก ZIP เต็ม v33.10 **ลงโฟลเดอร์ใหม่ก่อน** ตรวจเทียบกับโค้ดปัจจุบันบน GitHub ที่อาจมี Commit จากโรงเรียนหรือบ้านใหม่กว่าเวอร์ชัน ZIP เดิม
3. ต้องติดตั้ง Migrations เดิมถึง `202611230032_sports_admin_result_corrections_v33_9.sql` ครบก่อน
4. ใน Supabase SQL Editor รันไฟล์ **`supabase/migrations/202611230033_sports_admin_full_control_v33_10.sql`** (การติดตั้งไม่แก้หรือลบทะเบียนเดิม)
5. คัดลอกโค้ดที่เพิ่ม/แก้ไปโปรเจกต์ปัจจุบัน แล้วรัน `npm run build`
6. หาก Build ผ่าน Commit และ Push → ตรวจ Vercel Deployment
7. เปิด `/group-sports/admin` ด้วยบัญชี Admin หลัก
8. ทดลองกับใบสมัครในฐานทดสอบ แล้วตรวจชื่อ รายชื่อครู รูป คำร้องขอ และประวัติทั้งก่อน/หลัง
9. หากมีเอกสารรางวัล ตรวจว่า QR เก่าเป็นสถานะถูกยกเลิก ขณะที่โรงเรียนพิมพ์เอกสารใหม่ได้ถูกต้อง

## สถานะการทดสอบก่อนส่งมอบ

ตรวจไวยากรณ์ไฟล์ TypeScript/TSX ด้วย TypeScript parser และตรวจโครงสร้าง SQL/ZIP แบบออฟไลน์ ยังไม่ได้ยืนยันการรัน SQL บน Supabase Production หรือ `npm run build` ด้วย dependencies ของเครื่องผู้ใช้ จึงจำเป็นต้องทดสอบกับฐานข้อมูลทดสอบก่อนเปิดใช้งานจริง
