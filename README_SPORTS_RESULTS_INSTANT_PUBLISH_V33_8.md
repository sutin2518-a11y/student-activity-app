# ระบบกีฬากลุ่ม v33.8 — ส่งผลแล้วประกาศทันที ไม่มีขั้นตอน Admin อนุมัติ

## นโยบายการทำงานใหม่

1. โรงเรียนส่งใบสมัครแล้วถือว่าระบบรับข้อมูลทันที ไม่ต้องรอ Admin ตรวจหรืออนุมัติ
   - กีฬาเดี่ยว/ทีมที่ใช้ `sports_entries`: ใช้ trigger auto-receive จาก migration `202611220020_sports_entries_auto_receive_on_site_check.sql` ซึ่งปรับ `submitted` เป็น `approved` ภายในฐานข้อมูลเพื่อคงความเข้ากันได้กับ query เดิม โดยหน้าจอแสดงเป็น “รับข้อมูลแล้ว · ตรวจที่สนาม” ไม่ได้หมายถึง Admin อนุมัติ
   - ฟุตบอล 4 ประเภท: RPC `sports_football_register` บันทึกใบสมัครเป็น `approved` ทันทีอยู่แล้ว
   - การตรวจตัวจริง/คุณสมบัติและเอกสารหลักฐานทำที่สนามแข่งขัน
2. Admin มีหน้าที่มอบหมาย/ระงับกรรมการรายรายการ และจัดการแม่แบบ/เอกสารเกียรติบัตร ไม่ตรวจผลทุกกีฬา และจะบันทึกผลไม่ได้เว้นแต่ตั้งใจมอบหมายอีเมลของตนเองเป็นกรรมการในรายการนั้น
3. กรรมการที่ได้รับมอบหมายเลือกอันดับแล้วกด “ประกาศผลและออกเกียรติบัตรทันที”
4. เฉพาะอีเมล Google ที่ยืนยันแล้วและได้รับมอบหมายตรงกับรายการเท่านั้นที่บันทึกผลได้ การส่งผลจะทำงานใน transaction เดียว: เปลี่ยนสถานะเป็น `published`, บันทึกอันดับ, sync ตาราง `sports_event_results`, สร้างเหรียญใน `sports_medals` และออกเกียรติบัตรรางวัล
5. โรงเรียนเข้าพิมพ์เกียรติบัตรรางวัลได้ทันทีตามสิทธิ์บัญชีโรงเรียน และหน้า Dashboard สมัครรับ Supabase Realtime เพื่ออัปเดตตารางผล/เหรียญโดยไม่ต้องกดรีเฟรช (หาก publication มีสิทธิ์เปิดใช้งาน)
6. ปิด RPC อนุมัติ/ส่งกลับ/เผยแพร่ผลแบบเดิม `sports_cert_review` โดย revoke สิทธิ์ authenticated

## ไฟล์ในแพตช์

- `src/components/group-sports/CertificatesDashboard.tsx` — เอาหน้าตรวจ/อนุมัติผลออก และเปลี่ยนปุ่มกรรมการเป็นประกาศผลทันที
- `src/components/group-sports/GroupSportsDashboard.tsx` — เอาเมนู “ตรวจสอบ / อนุมัติผล” ออก และปรับข้อความเมนู/ผลการแข่งขัน
- `src/lib/group-sports/certificates.ts` — ปรับป้ายสถานะผลให้ตรงกับ workflow ใหม่
- `src/app/group-sports/results/page.tsx` — ปรับคำอธิบายหน้าบันทึกผล
- `src/app/group-sports/certificates/manage/page.tsx` — ปรับคำอธิบายหน้า Admin ให้ไม่มีขั้นอนุมัติผล
- `src/app/group-sports/results/review/page.tsx` — redirect URL เก่าไปหน้าบันทึกผล เพื่อรองรับ bookmark เดิม
- `supabase/migrations/202611230031_sports_results_instant_publish_v33_8.sql` — ปรับ RPC ให้ประกาศผลทันทีและปิด RPC review เดิม

## วิธีติดตั้ง

1. สำรองโปรเจกต์และฐานข้อมูล Supabase ก่อน
2. ตรวจว่าได้ติดตั้ง migration `202611230027_sports_certificates_v1.sql` แล้ว
3. ตรวจว่าได้ติดตั้ง migration `202611220020_sports_entries_auto_receive_on_site_check.sql` แล้ว (เป็นนโยบายรับใบสมัครทันที)
4. วางไฟล์จากแพตช์ตาม path ทับโปรเจกต์ v33.7.1 ปัจจุบัน ห้ามแตกทับทั้งโปรเจกต์ด้วย ZIP ฉบับเต็มเก่า
5. เปิด Supabase SQL Editor แล้วรัน `202611230031_sports_results_instant_publish_v33_8.sql` เพียงครั้งเดียว
6. รัน `npm run build`
7. ทดสอบในรายการทดสอบก่อน: ให้โรงเรียนส่งใบสมัคร, Admin มอบหมายกรรมการ, กรรมการส่งอันดับ แล้วตรวจว่าผลปรากฏในตารางผล/ตารางเหรียญและโรงเรียนพิมพ์เกียรติบัตรได้
8. Commit + Push เพื่อ Deploy

## ข้อควรทราบ

- Migration นี้ไม่เปลี่ยน/ลบใบสมัครเดิม และไม่ auto-publish ผลเก่าที่ค้างสถานะ `submitted` หรือ `approved` เพื่อป้องกันการเผยแพร่ข้อมูลทดลองโดยไม่ตั้งใจ กรรมการสามารถเปิดรายการเดิม ตรวจอันดับ แล้วกดประกาศผลเพื่อเผยแพร่ได้
- เมื่อประกาศแล้ว รายการจะล็อกไม่ให้ส่งซ้ำเพื่อป้องกันเกียรติบัตรซ้ำ หากพบความผิดพลาดให้ใช้ระบบยกเลิก/ออกเกียรติบัตรฉบับใหม่ตามขั้นตอนที่มีอยู่ และประสานผู้ดูแลแก้ไขเอกสารที่เกี่ยวข้อง
- การส่งผลเป็นการประกาศทันทีในฐานข้อมูลกลาง หน้า Dashboard จะรับ Realtime จาก `sports_event_results` และ `sports_medals`; หาก migration แจ้งว่าเปิด publication ไม่ได้ ให้เพิ่มสองตารางนี้ใน `supabase_realtime` หรือใช้การรีเฟรชหน้าเป็นทางสำรอง ไม่ใช่การรอ Admin กดอนุมัติ
- ระบบฟุตบอลและ RoV ยังคงใช้หน้าจอ/ผลคะแนนแมตช์เฉพาะเดิม การส่งอันดับในหน้านี้ใช้สำหรับผลอันดับสุดท้ายและเกียรติบัตรเท่านั้น
- ยังไม่ได้ทดสอบกับ Supabase Production จริง ต้องทดสอบกับข้อมูลจำลองก่อนใช้งานจริง
