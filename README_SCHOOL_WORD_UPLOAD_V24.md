# ระบบกีฬากลุ่ม v24 — ส่งข้อมูลโรงเรียนด้วย Word เท่านั้น + สรุปติดตาม 21 โรงเรียน

## วัตถุประสงค์
- โรงเรียนกดดาวน์โหลดแบบฟอร์ม Word ต้นฉบับที่กำหนดโดยผู้จัดการแข่งขัน
- กรอกข้อมูลโรงเรียนทั้งหมด 18 ข้อ **ใน Microsoft Word** แล้วอัปโหลด `.docx` ผ่านหน้า “ส่งข้อมูลโรงเรียน” เท่านั้น
- ยกเลิกการบังคับกรอกข้อมูลโรงเรียนและคำบรรยายบนหน้าเว็บ
- ติดตามสถานะ **ยังไม่ส่ง / ส่งแล้วรอตรวจ / ส่งคืนแก้ไข / รับรองแล้ว** แยกรายโรงเรียนและสรุปจำนวนทั้งหมด
- เก็บเอกสารใน private Storage bucket เดิม (`sports-school-submissions`) ตามนโยบาย RLS เดิม
- กรรมการดาวน์โหลดไฟล์และส่งคืนแก้ไข/รับรองผ่านกลไกเดิมได้

## รายละเอียดของแบบฟอร์ม
`public/templates/school-information-phulangka-games-2569.docx` เป็นสำเนาแบบไม่ดัดแปลงจากไฟล์ผู้ใช้แนบมา
`แบบฟอร์มข้อมูลโรงเรียนที่เข้าร่วมการแข่.docx` ข้อมูล 18 หัวข้อ ตามแบบการแข่งขัน “ภูลังกาเกมส์” ปีการศึกษา 2569 (1–11 ธันวาคม 2569)

**หมายเหตุ:** ระบบไม่ได้อ่านหรือแปลงเนื้อหาใน Word เป็นข้อมูลโครงสร้างของทะเบียนโรงเรียนอัตโนมัติ ถ้าต้องแก้ชื่อผู้อำนวยการเพื่อใช้ในใบสมัครกีฬา ให้แก้ในเมนู “โรงเรียน” ตามระบบเดิมด้วย

## ไฟล์ที่เพิ่ม/ปรับ
1. `src/components/group-sports/SchoolSubmissionsContent.tsx` — UI ใหม่ + ส่ง Word อย่างเดียว + สรุปสถานะ
2. `public/templates/school-information-phulangka-games-2569.docx` — Word ต้นฉบับสำหรับดาวน์โหลด
3. `supabase/migrations/202611220019_school_word_only_progress.sql` — RPC ใหม่ สรุปสถานะทุกโรงเรียนโดย **ไม่เผยข้อมูลภายในไฟล์**

ไม่มีการแก้ไขระบบลงทะเบียนนักกีฬา, RoV, ภาพนักกีฬา, บัญชีโรงเรียน, Auth และระบบพิมพ์ PDF

## ขั้นตอนติดตั้ง (จาก v23)
1. สำรอง Supabase ก่อนรัน SQL
2. เปิด Supabase SQL Editor แล้วรัน `supabase/migrations/202611220019_school_word_only_progress.sql`
3. แตก Patch v24 ทับโครงการ v23 (คงโครงสร้างโฟลเดอร์)
4. Commit / Push ผ่าน GitHub Desktop
5. ทดลองบน Vercel Preview ที่ตั้งค่าตัวแปรและฐานข้อมูลทดสอบครบ หรือทดสอบใน Production อย่างระมัดระวัง
6. เข้าระบบด้วยบัญชีโรงเรียนหนึ่งแห่ง ไปที่ “ส่งข้อมูลโรงเรียน” ดาวน์โหลด Word → กรอก 18 ข้อ → บันทึก `.docx` → อัปโหลด → ส่ง
7. เข้า Admin ตรวจสถานะ 21 โรงเรียน เปิดดูไฟล์ และลอง “ส่งคืนแก้ไข” ให้โรงเรียนส่งไฟล์ใหม่
8. ทดสอบว่าบัญชีโรงเรียนอื่นเห็นเฉพาะสถานะของทุกโรงเรียน แต่ไม่เปิดไฟล์ Word ของโรงเรียนอื่นได้

ไม่ต้องสร้าง Storage Bucket ใหม่ ไม่ต้องเพิ่ม Environment Variables ใหม่ เพราะใช้ของเดิม

## ความหมายสถานะ
- **ยังไม่ส่ง:** ไม่มีใบรับข้อมูลในฐานข้อมูลสำหรับการแข่งขันนี้
- **ส่งแล้ว · รอตรวจ:** อัปโหลดและบันทึกสำเร็จ แต่กรรมการยังไม่ตรวจรับ
- **ส่งคืนแก้ไข:** เคยส่งแล้ว แต่ต้องแก้ไฟล์ Word และส่งใหม่ (นับรวมในจำนวน “ส่งแล้ว”)
- **รับรองแล้ว:** ตรวจรับเอกสารแล้ว และล็อกการส่งใหม่ตามนโยบายเดิม

## หมายเหตุเกี่ยวกับข้อมูลเดิม
- ไม่ลบข้อมูลคำบรรยาย/เบอร์ติดต่อ/ผู้อำนวยการเดิมที่เคยกรอกผ่านเว็บ
- RPC เดิมบังคับพารามิเตอร์ `contact_name` จึงใส่ข้อความ “ข้อมูลตามแบบฟอร์ม Word” เฉพาะเมื่อสร้างข้อมูลใหม่ และใช้ค่าเดิมถ้าเคยมี
- เอกสาร PDF ที่เคยแนบไว้ในรายการเก่าไม่ถูกลบ และคงอ้างอิงเดิม แต่หน้าอัปโหลดใหม่รับเฉพาะ Word `.docx`
- หาก SQL 0019 ยังไม่รัน หน้าใหม่จะแจ้งให้ติดตั้ง Migration ไม่ควรลบตารางหรือแก้ RLS โดยไม่มีการทดสอบ

## สถานะการทดสอบ
- ผ่านการตรวจไวยากรณ์ TSX/TypeScript แบบ parser (ไม่ใช่ Production Build เต็มรูปแบบ)
- ตรวจสอบความถูกต้องของไฟล์ Word ที่เตรียมดาวน์โหลดและ render ภาพตัวอย่างแล้ว
- ยังไม่ได้ทดสอบกับ Supabase จริง, RLS, Storage หรือ Vercel; โปรดทดสอบก่อนใช้งานทั้ง 21 โรงเรียน
