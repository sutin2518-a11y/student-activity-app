# ระบบกีฬากลุ่ม v33.13 — เปลี่ยนภาพและแก้ข้อความข้อมูลทั่วไป

ฐานโค้ด: **v33.12 เมนูข้อความล้วน** พร้อมสิทธิ์และระบบกีฬาเดิมทั้งหมด

## สิ่งที่เพิ่ม

1. เปลี่ยนภาพที่แสดงโดยค่าเริ่มต้นด้วย **ภาพจริงที่ผู้ใช้ส่งมา** (ไม่ใช่ภาพที่ AI วาดใหม่)
   - **แผนผังการยืนขบวนในสนาม** และ **อัฒจันทร์กองเชียร์** ใช้ไฟล์ภาพแผนผังสนามเดียวกัน `opening-ceremony-and-cheer-stands-2569-v33-13.png`
   - **ลำดับขบวน** ใช้ `parade-order-2569-v33-13.png`
   - **จุดตั้งขบวน** ใช้ `parade-assembly-location-2569-v33-13.png`
   - ภาพ Preview แยกเป็น WebP ที่อ่านง่ายและโหลดเร็วขึ้น แต่ปุ่มขยายใช้ภาพ PNG ต้นฉบับที่ผู้ใช้ให้ไว้
   - เปลี่ยนชื่อไฟล์ภาพเป็น `v33-13` เพื่อไม่ให้เบราว์เซอร์/แคช Vercel แสดงภาพเก่า
2. **Admin จัดการภาพและข้อความหลักแยกตามหัวข้อ** ผ่าน `ข้อมูลทั่วไป → จัดการภาพและข้อความ (Admin)` หรือ URL `/group-sports/information/manage`:
   - เปลี่ยนหัวเรื่อง/ข้อความอธิบาย/ลิงก์ Google Maps และอัปโหลดภาพ JPG/PNG/WebP ไม่เกิน 12 MB
   - เห็นตัวอย่างภาพก่อนบันทึก หรือกลับไปใช้ภาพต้นแบบ
   - การบันทึกภาพหลักเผยแพร่ทันที และผูกกับคีย์ประเภท (`parade_map`, `cheer_stands`, `parade_order`, `assembly_points`) ไม่ใช่ชื่อหัวเรื่องที่เปลี่ยนได้
   - ใช้ private bucket `sports-school-information` และตรวจสิทธิ์ Admin ผ่าน RLS เดิม
3. แก้บั๊ก **ปุ่มแก้ไขของรายการที่เผยแพร่แล้วเป็น Disabled**: Admin สามารถแก้ชื่อเรื่อง/รายละเอียด/Google Maps/ไฟล์แนบได้โดยตรง ข้อมูลยังคงเผยแพร่ระหว่างแก้ไข ไม่ต้องถอนเผยแพร่และเผยแพร่อีกครั้ง
4. เมื่อบันทึกสำเร็จ รีเฟรชข้อมูลในหน้า Admin ทันที และหน้าที่เปิดอยู่ของผู้ชมจะอ่านข้อมูลใหม่ภายในประมาณ 30 วินาที (หรือทันทีที่กลับมาที่แท็บ); ใช้การอ่าน Supabase ไม่ได้พึ่ง cache ที่ผูกกับชื่อหัวเรื่อง
5. รายการประกาศเพิ่มเติมเดิมยังอยู่ ไม่ถูกลบ ไม่ยกเลิกการเผยแพร่ ไม่แตะระบบลงทะเบียน/ฟุตบอล/RoV/ผล/เกียรติบัตร

## วิธีติดตั้ง (สำคัญ)

1. **สำรอง Git Commit ล่าสุดและฐานข้อมูล Supabase** ก่อน โดยเฉพาะหากมี Commit จากเครื่องโรงเรียนหลัง v33.12
2. แตก ZIP เต็ม **ลงโฟลเดอร์ใหม่ก่อน** แล้วค่อยรวมไฟล์ที่แก้กับ Branch ล่าสุด อย่าวางทับทั้งโปรเจกต์ทันทีถ้า Branch บน GitHub ใหม่กว่า ZIP
3. Supabase SQL Editor: รัน `supabase/migrations/202611230035_sports_information_primary_media_v33_13.sql` **หลัง** migration 202611220021 และ 202611220022 ครบแล้ว (หากเคยใช้ v33.12 มาก่อนควรมีอยู่แล้ว)
   - migration นี้เพิ่ม `is_primary` และ unique index สำหรับข้อมูลภาพหลัก ไม่ลบหรือเปลี่ยนสถานะข้อมูลประกาศเดิม
   - ต้องรัน SQL ก่อน Deploy โค้ดใหม่ มิฉะนั้นหน้าอ่านข้อมูลจะขึ้น error `is_primary does not exist`
4. เปิด VS Code จากโฟลเดอร์โปรเจกต์ที่รวมโค้ดแล้ว รัน `npm install` เมื่อจำเป็น แล้ว `npm run build`
5. หาก build ผ่าน ให้ Commit และ Push แล้วตรวจ Vercel Production/Preview ตาม Branch ปัจจุบัน
6. เปิดเมนู `ข้อมูลทั่วไป` ทั้ง 4 หน้าบนหน้าเว็บ เพื่อตรวจภาพที่แนบและการขยายภาพ
7. เข้าด้วยบัญชี Admin ที่มีบทบาท `super_admin` หรือ `competition_admin` ของการแข่งขัน แล้วเปิด `/group-sports/information/manage`
8. เลือกหัวข้อ กด **เปลี่ยนภาพหลัก / หัวเรื่อง / คำอธิบาย** แล้วลองแก้หัวเรื่อง บันทึก และเปิดหน้า public ในแท็บอื่น เพื่อตรวจผล
9. เปิดหน้ารายการที่เคยเผยแพร่แล้ว (เช่น `แผนที่และการนำทาง`) ทดลอง **แก้ไข** โดยไม่ต้องกดถอนเผยแพร่ก่อน

## ขอบเขตและข้อควรระวัง

- อัปโหลดภาพสำเร็จจึงเปลี่ยนข้อมูลบนหน้า Public; ถ้าอัปโหลดไม่ผ่าน ภาพ/ข้อความที่เผยแพร่เดิมยังอยู่
- เมื่อสร้างภาพหลักครั้งแรก ระบบสร้างรายการฉบับร่างให้รองรับสิทธิ์ Storage ก่อน แล้วอัปเดตเป็นเผยแพร่หลังบันทึกข้อมูลครบ
- การเปลี่ยนภาพไม่ลบไฟล์เดิมใน Storage โดยอัตโนมัติ เพื่อเก็บประวัติ ผู้ดูแลสามารถเปลี่ยนกลับไปใช้ภาพต้นแบบได้
- หน้า `/group-sports/information/manage` ตรวจสิทธิ์ก่อนแสดงฟอร์ม และฐานข้อมูล RLS เป็นตัวตัดสินสิทธิ์การอ่านและบันทึกจริง
- ข้อมูลหลักและประกาศเพิ่มเติมเป็นคนละรายการ; `is_primary` หนึ่งรายการต่อหนึ่งประเภทต่อการแข่งขัน
- ยังไม่ได้รัน migration นี้กับ Supabase ออนไลน์และยังไม่ยืนยัน Production Build กับ Next.js ที่ติดตั้ง dependencies ครบ; ต้องทดสอบหลังติดตั้ง
- ZIP เต็มไม่รวม `node_modules`, `.next`, `.env*` และ `public.zip` ซึ่งเคยเป็น ZIP สำรองค้าง; แต่มี `public/` ครบ
