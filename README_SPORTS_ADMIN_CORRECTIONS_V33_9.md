# ภูลังกาเกมส์ 2569 — v33.9: Admin แก้ไขผลหลังประกาศได้ (กรณีพิเศษ)

## การทำงาน (ไม่มีขั้นอนุมัติผล)

- โรงเรียนส่งใบสมัครแล้วระบบรับข้อมูลทันทีตามนโยบาย v25 (`status='approved'` หมายถึง **รับข้อมูลแล้ว**)
- กรรมการที่ได้รับมอบหมายประกาศผลตามรายการได้ทันที ตาม v33.8 ไม่ผ่าน Admin
- **Admin หลัก** เข้าหน้า **จัดการแข่งขัน → แก้ไขผลหลังประกาศ (Admin)** หรือ `/group-sports/results/corrections` เฉพาะกรณีกรรมการแจ้งให้แก้ผลที่ประกาศแล้ว
- แก้ไขอันดับชนะเลิศ รองชนะเลิศอันดับที่ 1 และรองชนะเลิศอันดับที่ 2; กีฬาทั่วไปมีอันดับ 3 ร่วม 2 ทีม ส่วนกรีฑาไม่มีอันดับ 3 ร่วม
- แก้ไขพร้อมเหตุผลอย่างน้อย 8 ตัวอักษร ต้องยืนยันอีกครั้งก่อนบันทึก
- ใน **transaction เดียว** ระบบตรวจข้อมูล/สิทธิ์/ความใหม่, อัปเดตอันดับและตารางเหรียญ, ยกเลิกเกียรติบัตร **รางวัล** เดิม (เลขที่และ QR เดิมยังตรวจสอบประวัติได้), ออกเกียรติบัตรรางวัลชุดใหม่ด้วยเลขที่และ QR ใหม่, และบันทึกประวัติการแก้ไข
- **เกียรติบัตรเข้าร่วม** ไม่ถูกยกเลิกเมื่อแก้อันดับ (ไม่มีผลต่อการเข้าร่วม)
- แก้ไขผลได้หลายครั้ง ทุกครั้งมีประวัติ ผู้แก้ วันเวลา ผลเดิมและผลใหม่
- หากข้อมูลถูกเปลี่ยนจากอีกหน้าระหว่างแก้ไข ระบบปฏิเสธการบันทึกและให้โหลดข้อมูลใหม่
- กรรมการทั่วไปและบัญชีโรงเรียนไม่มีสิทธิ์เรียกฟังก์ชันแก้ผลย้อนหลัง แม้พิมพ์ URL ตรง

## ขอบเขตที่ควรทราบ

- นี่คือการแก้ไข **อันดับรางวัลสุดท้าย** สำหรับรายรายการแข่งขัน ไม่ใช่ระบบแก้คะแนนรายแมตช์ ฟุตบอล/ROV ยังคงบริหารคะแนนแต่ละคู่ด้วยหน้ากีฬาเฉพาะ
- ไม่มีการเปิดขั้นตอนให้ Admin อนุมัติ/ปฏิเสธผลตามปกติ และไม่แก้กติกาใบสมัครของโรงเรียน
- การเปลี่ยนผลจะส่งผลให้เกียรติบัตรรางวัลเดิมทั้งหมดของรายการถูกยกเลิกและออกใหม่ (รวมผู้ได้รับรางวัลที่อันดับไม่เปลี่ยน) เพื่อให้เอกสารในรายการเป็นรุ่นเดียวกัน
- เอกสารเดิม/QR ไม่ถูกลบ; มีเหตุผลและชื่อ Admin ที่ดำเนินการอยู่ในประวัติ
- หากไม่มีนักกีฬา/ครูในรายชื่อใหม่พอที่จะออกเกียรติบัตร ระบบจะ **ยกเลิกรายการแก้ทั้งหมด** ไม่ทิ้งข้อมูลครึ่งทาง
- **ต้องมี Migration 202611230032 และ Migration ก่อนหน้าถึง 031** จึงจะใช้ฟังก์ชันนี้ได้
- ขณะจัดทำโค้ดนี้ **ยังไม่ได้ติดตั้ง SQL กับ Supabase ออนไลน์หรือทดสอบ npm run build สำเร็จ** เนื่องจากสภาพแวดล้อมไม่มี node_modules; ต้องตรวจบนเครื่องผู้ดูแลก่อนใช้งานจริง

## วิธีติดตั้งจาก ZIP เต็ม v33.9

1. สำรองฐานข้อมูล Supabase และภาพใน Storage ก่อน และ Commit/สำรองโปรเจกต์ Git ปัจจุบันบนเครื่อง
2. ZIP เต็มนี้ประกอบจาก **โปรเจกต์ v33.6 ที่เคยส่งมา + แพตช์ v33.7.1 + v33.8 + งานใหม่ v33.9** หาก GitHub มี Commit อื่นที่ไม่ได้อยู่ใน ZIP นี้ ให้ตรวจ diff ก่อนทับ อย่าลบงานบนเครื่องที่ใหม่กว่า
3. แตก ZIP ในโฟลเดอร์แยกก่อน แล้วคัดลอก/รวมไฟล์ที่ต้องการเข้ารหัสหลัก (หลีกเลี่ยงการทับไฟล์แก้ล่าสุดจากโรงเรียนโดยไม่ตรวจสอบ)
4. บน Supabase SQL Editor ตรวจว่า Migration 027, 029, 030 และ 031 ติดตั้งแล้ว จากนั้นรัน **`supabase/migrations/202611230032_sports_admin_result_corrections_v33_9.sql`** (ติดตั้งอย่างเดียว **ไม่แก้ผลการแข่งขันจริง**)
5. บน VS Code ที่มี dependencies รัน `npm ci` (หากยังไม่มี `node_modules`) แล้ว `npm run build`
6. หาก Build ผ่าน ให้ Commit และ Push ผ่าน GitHub Desktop และตรวจ Vercel Production
7. ใช้บัญชี Admin เปิด `/group-sports/results/corrections` แล้วเลือกรายการที่ประกาศแล้ว แก้อันดับ และระบุเหตุผล ทดสอบกับ **ฐานข้อมูลทดสอบ** ก่อนเปิดใช้ Production
