# ระบบกีฬากลุ่ม v8 — สุ่มบัญชีให้ทุกโรงเรียนที่เข้าร่วมการแข่งขัน

## ความสามารถ

- หน้าผู้ดูแล `/group-sports` → **บัญชีโรงเรียน** มีปุ่ม **สุ่มบัญชี N โรงเรียน**
- ดึงรายชื่อจาก `sports_competition_schools` เฉพาะการแข่งขัน `phayao-secondary-group-sports-2569` และเฉพาะโรงเรียนที่ยัง active
- สร้างบัญชี **เฉพาะโรงเรียนที่ยังไม่มีบัญชี** ใน `sports_school_accounts` ไม่รีเซ็ตรหัสผ่านเดิม ไม่สร้างซ้ำ
- Username อัตโนมัติรูปแบบ `py001`, `py002`, ... (ตัวเลขถัดไปที่ยังว่างในการแข่งขันนี้)
- รหัสผ่านสุ่มแบบเข้ารหัสแข็งแรง 24 ตัวอักษรด้วย `crypto.randomBytes` บนเซิร์ฟเวอร์; Supabase Auth เก็บแฮชรหัสผ่าน
- ระบบแบ่งสร้างครั้งละไม่เกิน 4 โรงเรียน พร้อมแสดงแถบความคืบหน้าและผลสำเร็จ/ข้าม/ไม่สำเร็จ
- หลังสร้าง ระบบแสดงรหัสผ่าน **ครั้งเดียว** แยกตามโรงเรียน พร้อมปุ่มคัดลอกสำหรับส่งเฉพาะโรงเรียนนั้น และดาวน์โหลด Excel สำหรับ Admin
- Excel มีชื่อโรงเรียน, Username, Password, URL `/group-sports/login`, และคำแนะนำ
- รายงาน Excel มีข้อมูลลับของทุกโรงเรียน: **ห้ามส่งไฟล์รวมให้โรงเรียนหรือในกลุ่มไลน์** ควรแจกโดยตรงเป็นรายโรงเรียน และลบไฟล์เมื่อใช้เสร็จ
- ถ้าการสร้างบางชุดไม่สำเร็จ บัญชีที่สร้างสำเร็จแล้วจะไม่ถูกเปลี่ยนอีก การกดซ้ำจะจัดการเฉพาะโรงเรียนที่ยังไม่มีบัญชี

## การติดตั้ง

1. ใช้โครงการ **v7 Hotfix** ซึ่งผ่าน Build แล้วเป็นฐาน (หรือเวอร์ชันใหม่กว่าที่มี v7)
2. นำไฟล์ Patch v8 แตกลงในโฟลเดอร์โครงการโดยรักษาเส้นทางเดิม
3. ไม่ต้องรัน SQL ใหม่ แต่ **ต้องรัน Migration 0012 ของ v7** ไว้แล้ว
4. ใน Vercel → Project Settings → Environment Variables ตรวจว่ามี:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` (Secret; เฉพาะเซิร์ฟเวอร์)
   - `SPORTS_ACCOUNT_EMAIL_DOMAIN` (Config เช่นโดเมนย่อยขององค์กรที่ควบคุมเอง ไม่ต้องมีกล่องจดหมายจริง)
5. บันทึก Environment Variables แล้ว Deploy ใหม่ หากเพิ่งเพิ่ม/แก้ไข
6. ใช้บัญชี Admin เข้าหน้ากีฬากลุ่ม → บัญชีโรงเรียน ตรวจว่าไม่ขึ้นคำเตือนตั้งค่าโดเมน
7. กด **สุ่มบัญชี N โรงเรียน** และยืนยัน จากนั้นดาวน์โหลด Excel และแยกส่ง Username/Password ให้แต่ละโรงเรียน
8. ทดสอบเข้าสู่ระบบด้วยบัญชีโรงเรียนอย่างน้อย 2 โรงเรียน และทดสอบว่าข้อมูลของแต่ละโรงเรียนแยกจากกัน
9. เมื่อผ่านทดสอบ Preview แล้ว Merge Branch เข้า `main` เพื่อ deploy Production ตามขั้นตอนเดิม

## ความปลอดภัยและข้อจำกัด

- API ใหม่: `POST /api/group-sports/school-accounts/bulk` (Bearer Token Admin, จำกัด 4 โรงเรียนต่อคำขอ, ตรวจว่าร่วมแข่งขันจริง)
- API ตั้ง `Cache-Control: private, no-store`; ไม่มีการบันทึกรหัสผ่านในตารางหรือ logs และไม่สามารถอ่านย้อนหลังได้
- ใช้ข้อจำกัด `unique(competition_id, school_id)` และ `unique(competition_id, username)` จาก Migration 0012 ป้องกันซ้ำ
- กรณีสร้าง Auth user สำเร็จแต่ผูกบัญชี/สิทธิ์ไม่ผ่าน จะพยายามลบ Auth user เพื่อ rollback
- หากเน็ตหลุดหลังเซิร์ฟเวอร์สร้างบัญชีสำเร็จแต่ก่อน Browser ได้รับรหัสผ่าน จะไม่สามารถดูรหัสผ่านเดิมได้ ต้องให้ Admin รีเซ็ตบัญชีนั้นในหน้ารายการบัญชี
- หากมีผู้ดูแล 2 คนสร้างบัญชีพร้อมกัน ฐานข้อมูลจะป้องกันบัญชีซ้ำ และรายการขัดแย้งอาจถูกรายงานว่า "ข้าม" หรือ "ไม่สำเร็จ" ให้ Refresh และตรวจผล
- ยังไม่ได้ทดสอบการบันทึกกับ Supabase จริงหรือ Next.js Production Build ในสภาพแวดล้อมการจัดทำนี้
