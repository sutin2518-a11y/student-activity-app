# ระบบกีฬากลุ่ม v30.3 — รีเซตข้อมูลทดสอบ RoV ก่อนใช้งานจริง

## จุดประสงค์

รีเซตข้อมูล **เฉพาะระบบจัดการแข่งขัน RoV (E-Sport)** ทั้งทีมชายและทีมหญิง โดยไม่ไปแตะระบบลงทะเบียนนักกีฬา โรงเรียน กีฬาอื่น กลุ่มการแข่งขัน หรือคู่แข่งขันรอบแบ่งกลุ่มที่จัดไว้

## การติดตั้งจาก v30.2

1. **สำรองฐานข้อมูล Supabase ด้วยวิธีที่องค์กรใช้อยู่ก่อนเสมอ** (แนะนำดาวน์โหลด CSV ตาราง E-Sport สำคัญเพิ่มเติมด้วย)
2. เปิด Supabase SQL Editor แล้วรันไฟล์ `supabase/migrations/202611220024_esports_prelaunch_reset.sql` **หนึ่งครั้ง** หลัง Migration 0004/0005/0006 และ 0023 ที่ติดตั้งอยู่ในระบบเดิม
3. แตก Patch v30.3 ทับโปรเจกต์ v30.2 โดยให้ไฟล์ `src/app/group-sports/esports/page.tsx` ไปอยู่ที่เดิม
4. Commit และ Push ผ่าน GitHub Desktop แล้วตรวจการ Deploy ใน Vercel
5. เข้าสู่ระบบด้วย **บัญชีที่มีบทบาท Admin ในการแข่งขัน** (สิทธิ์ตรวจสอบจริงผ่าน `sports_stage3_admin` ในฐานข้อมูล)
6. เปิด `/group-sports/esports` แล้วเลือกแท็บ **เตรียมใช้จริง / รีเซตทดสอบ**
7. กด **ตรวจสอบข้อมูลที่จะรีเซต** เพื่อดูจำนวนคู่ชาย/หญิง คู่ cancelled/completed และประวัติที่มีอยู่
8. ตรวจสอบว่าตั้งใจรีเซตข้อมูลทั้งหมดจริง ๆ แล้วเลือกเครื่องหมายยอมรับและพิมพ์ข้อความ **`รีเซต ROV 2569`** ตามตัวอักษร
9. ยืนยันในกล่องข้อความอีกครั้ง ระบบจะสร้าง **archive** แล้วรีเซตใน transaction เดียวกัน
10. ตรวจโปรแกรมและวันเวลาในตารางอีกครั้ง จากนั้นจึงกด **เผยแพร่โปรแกรม** ใน v30.2 เมื่อพร้อมใช้จริง

> **อย่ารันคำสั่งรีเซตในฐานข้อมูล Production หากยังไม่ได้สำรองข้อมูลหรือตรวจความถูกต้องของคู่แข่งขัน/วันเวลา** การติดตั้ง SQL เพียงอย่างเดียวไม่ได้ล้างข้อมูลใด ๆ

## ผลการรีเซต

| รายการ | หลังรีเซต |
|---|---|
| รายชื่อโรงเรียน ทีมและนักกีฬา | คงเดิม |
| การแบ่งกลุ่ม A–D และทีมในกลุ่ม | คงเดิม |
| คู่พบกันหมดของแต่ละกลุ่ม | คงเดิม |
| วันที่ เวลา สนาม และลำดับคู่รอบแบ่งกลุ่ม | คงเดิม |
| สถานะ cancelled / completed / scheduled / draft ของคู่รอบแบ่งกลุ่ม | เปลี่ยนเป็น `draft` ทั้งหมด; รอเผยแพร่ใหม่ |
| คะแนน ผลชนะ–แพ้ เวลาแข่งขัน Kill หมายเหตุ | ล้างเป็นค่าว่าง |
| ตารางคะแนน | คำนวณใหม่จากข้อมูลว่าง จึงกลับเป็นศูนย์ |
| รอบ Knockout | ยังคงโครงสายและการเชื่อมโยงไว้ แต่ล้างรายชื่อทีมในคู่ ผล เวลาและสถานะทดลอง |
| ประวัติทดลองที่แสดงบนหน้า E-Sport | ล้างออกจากหน้าปกติ หลังสำรองข้อมูลเดิมไว้ใน archive |
| กีฬาอื่น บัญชีและข้อมูลโรงเรียน | ไม่แก้ไข |

## ระบบป้องกัน

- Function `sports_esports_prelaunch_reset` ใช้ได้เฉพาะผู้เข้าระบบที่ `sports_stage3_admin` อนุญาตเท่านั้น
- ต้องกดดู Preview และใช้ fingerprint ที่ตรงกับข้อมูลล่าสุด จึงจะกดรีเซตได้ หากมีผู้แก้ข้อมูลหลัง Preview จะบังคับตรวจใหม่
- ต้องพิมพ์ข้อความยืนยันตรง และยืนยันในหน้าต่างเตือนอีกครั้ง
- บันทึก snapshot ของการแข่งขัน **ก่อน** ล้างข้อมูลลงตาราง `sports_esports_prelaunch_reset_archives` ซึ่งมี RLS ให้ Admin อ่านได้เท่านั้น
- Transaction เป็นแบบ all-or-nothing: หากสร้างสำเนาหรือรีเซตผิดพลาด จะ rollback ทั้งชุด
- ปิดการรีเซตตั้งแต่ **5 ธันวาคม 2569 ตามเวลาประเทศไทย** เพื่อป้องกันการลบผลการแข่งขันจริง
- **ไม่มีปุ่มกู้คืนอัตโนมัติ** หากจำเป็นต้องกู้คืน ให้ผู้ดูแลฐานข้อมูลตรวจสอบและกู้จาก snapshot/backup อย่างระมัดระวัง

## คำสั่งตรวจรายการสำรอง (อ่านข้อมูลอย่างเดียว)

```sql
select id, archived_at, archived_by, match_count, history_count
from public.sports_esports_prelaunch_reset_archives
order by archived_at desc;
```

ห้ามลบ archive จนกว่าคณะกรรมการยืนยันว่าไม่มีความจำเป็นต้องกู้ข้อมูลทดลอง

## การทดสอบ

- ตรวจไวยากรณ์ TSX และไฟล์ ZIP ในสภาพแวดล้อมพัฒนาแล้ว
- **ยังไม่ได้รัน SQL กับฐานข้อมูลจริงหรือทดลองการกู้คืนบน Supabase** และไม่ได้ยืนยัน Production Build/Deploy จริง
- ควรทดสอบ RPC ในฐานข้อมูล Preview/Staging ก่อนการใช้กับฐานข้อมูลการแข่งขันจริง
