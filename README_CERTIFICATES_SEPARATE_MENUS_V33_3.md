# v33.3 — แยกหน้าพิมพ์เกียรติบัตรออกจากหน้าบันทึกผล

วันที่: 23 พฤศจิกายน 2569

## เมนูและสิทธิ์

### สำหรับโรงเรียน: ข้อมูลทั่วไป → พิมพ์เกียรติบัตร (สำหรับโรงเรียน)

URL: `/group-sports/certificates`

- หน้านี้มีเฉพาะการค้นหารายการแข่งขัน เลือกประเภทเกียรติบัตรและผู้รับ เลือกชื่อ แล้วพิมพ์ PDF
- **ไม่มี** แท็บบันทึกผล อนุมัติ/เผยแพร่ หรือตั้งค่าระบบ
- Supabase RPC เดิม (`sports_cert_my_documents`) บังคับให้บัญชีโรงเรียนเห็นเอกสารของโรงเรียนตนเองเท่านั้น และแสดงเฉพาะเอกสารที่ออกแล้ว
- ผู้ดูแลการแข่งขันสามารถใช้หน้านี้พิมพ์เอกสารทั้งหมดตามสิทธิ์เดิม

### สำหรับกรรมการ: จัดการแข่งขัน → จัดการผลเกียรติบัตร (กรรมการ)

URL: `/group-sports/certificates/manage`

- เมนูจัดการแข่งขันแสดงลิงก์นี้เฉพาะเมื่อ `sports_cert_context` ยืนยันว่าเป็นกรรมการที่ได้รับมอบหมายหรือผู้ดูแลการแข่งขัน
- บัญชีกรรมการ (`official`) เห็นเฉพาะ **บันทึกผลการแข่งขัน** ของรายการที่ได้รับมอบหมาย
- ผู้ดูแล (`admin`) เห็นเฉพาะ **ตรวจสอบ / อนุมัติผล** และ **ตั้งค่าและมอบหมายกรรมการ**
- บัญชีโรงเรียนที่เปิด URL นี้โดยตรงจะได้รับหน้าปฏิเสธ พร้อมลิงก์ไปหน้าพิมพ์
- RPC เดิม `sports_cert_can_record`, `sports_cert_review`, `sports_cert_set_official` และ `sports_cert_my_documents` ควบคุมสิทธิ์ฝั่งฐานข้อมูลด้วย ไม่ใช่เพียงซ่อนปุ่ม

## การทำงานหลัก

1. ผู้ดูแลมอบหมายกรรมการแต่ละรายการในหน้าจัดการเกียรติบัตร
2. กรรมการเข้าหน้าจัดการและส่งผลอันดับ 1–3 โดยเลือกทีม/ผู้เล่นตามใบสมัครที่ได้รับแล้ว
3. ผู้ดูแลตรวจสอบ อนุมัติ และเผยแพร่ผล หรือเปิดพิมพ์เกียรติบัตรเข้าร่วม
4. โรงเรียนเข้าหน้าพิมพ์เกียรติบัตร เลือกรายการและพิมพ์เอกสารของตนเอง

## วิธีอัปเดต

1. สำรองโปรเจกต์ด้วย GitHub Desktop ก่อนแก้ไข
2. แตกไฟล์ `group-sports-certificates-v33.3-changed-files.zip` และคัดลอกไฟล์ลงโปรเจกต์ที่ใช้ **v33.2** อยู่แล้ว โดยรักษาโครงสร้างโฟลเดอร์
3. ทดสอบโค้ด: `node --experimental-strip-types --test tests/*.test.mjs` (ใช้ Node.js 22+) และ `npm run build`
4. Commit / Push และตรวจสอบทั้งบัญชีโรงเรียน กรรมการที่ได้รับสิทธิ์ และผู้ดูแลหลัง Deploy

ไม่ต้องรัน SQL ใหม่หรือเปลี่ยนข้อมูลเกียรติบัตรที่ออกแล้ว ทั้งสองหน้ากำลังเรียก RPC ชุดเดิมของ v33

**หมายเหตุ:** การพิมพ์เอกสารต้องใช้บัญชีผู้ดูแลหรือบัญชีที่ได้รับสิทธิ์โรงเรียนตามระบบเดิม บัญชีที่ได้รับบทกรรมการอย่างเดียวไม่ใช่บัญชีโรงเรียนสำหรับสั่งพิมพ์เอกสาร

## ผลการตรวจสอบในชุดนี้

- ตรวจไวยากรณ์ TSX ของไฟล์ที่แก้ไขทั้ง 4 ไฟล์ด้วย TypeScript transpilation แล้ว
- ผ่าน source/logic regression tests 10 รายการ (`node --experimental-strip-types --test tests/*.test.mjs`)
- **ยังไม่ได้ยืนยัน** Production Build, การเข้าสู่ระบบจริง และ RPC ผ่าน Supabase ออนไลน์ เพราะไม่มีแพ็กเกจ Next.js ในสภาพแวดล้อมทดสอบนี้
