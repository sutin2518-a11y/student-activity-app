# ระบบกีฬากลุ่ม — v14: ฟอร์มครูผู้ควบคุมเหมือน RoV ทุกประเภทกีฬา

## สิ่งที่เปลี่ยน

- ฟอร์มลงทะเบียนทีม/นักกีฬาของฟุตบอล วอลเลย์บอล เทเบิลเทนนิส กรีฑา กีฬาเดี่ยว/คู่ และ RoV แสดงส่วนครูผู้ควบคุมแบบเดียวกัน: ชื่อครู + เบอร์โทรศัพท์ และเพิ่ม/ลบครูหลายคนได้
- ต้องกรอกครูอย่างน้อย 1 คนและเบอร์โทรศัพท์ครบทุกคน (9–15 หลักหลังตัดช่องว่าง/ขีด)
- ไม่ต้องพิมพ์ชื่อทีม/ชื่อนักกีฬาในช่องแยก: กีฬาทีมและคู่ใช้ชื่อโรงเรียน ส่วนกีฬาเดี่ยวที่รับหนึ่งคนต่อใบสมัครใช้ชื่อนักกีฬา; หากแก้ไขใบสมัครที่ถูกส่งคืนจะคงชื่อใบสมัครเดิม
- ชื่อผู้ควบคุมทั้งหมดถูกบันทึกใน `sports_roster_staff.coaches` และอ่านกลับมาแสดงเมื่อเปิด/แก้ไขใบสมัคร
- เมื่อนำเข้า Excel สำหรับกีฬาเดี่ยว/กรีฑาหลายคน (หนึ่งคนต่อใบสมัคร) จะบันทึกรายชื่อครูชุดเดียวกันกับทุกใบสมัครอย่างอะตอมมิกใน RPC
- RoV ยังต้องมีตัวจริง 5 คน (หัวหน้าทีม 1 + ตัวจริง 4) ตัวสำรอง 0–2 คน, IGN และตำแหน่งที่เล่นเฉพาะ RoV
- ไม่มีช่องชั้นและเพศของนักกีฬา ระบบ Excel ที่มีอยู่ยังใช้งานตามเดิม

## ติดตั้งจาก v13.2

1. สำรองโค้ดและข้อมูล Supabase ก่อนทำการเปลี่ยนแปลงใน Production
2. รัน `supabase/migrations/202611220015_all_sports_coaches.sql` ผ่าน Supabase SQL Editor **หลัง** Migration 0014 ซึ่งเคยติดตั้งก่อนหน้า
3. แตกไฟล์ `student-activity-sports-roster-v14-patch.zip` ที่ root ของโปรเจกต์เดิม (รวมโฟลเดอร์ `src/` และ `supabase/`), อย่านำไปแตกซ้อนเพิ่มเป็นโฟลเดอร์อื่น
4. Commit → Push → ตรวจ Vercel Preview ว่า Build ผ่านและทดสอบลงทะเบียนจริงด้วยบัญชีโรงเรียนที่มีสิทธิ์ ก่อน Merge เข้า main

การปรับครั้งนี้ไม่ต้องเพิ่ม Environment Variables ใหม่

## ต้องทดสอบ

- เลือกเทเบิลเทนนิสเดี่ยว: มีช่องชื่อ+เบอร์ครูพร้อมปุ่มเพิ่ม/ลบ และลงทะเบียนนักกีฬา 1 คนได้
- เลือกกีฬาทีม: เพิ่มครู 2 คนแล้วส่งใบสมัครและเปิดดูพบครูทั้งสองพร้อมเบอร์
- เลือก RoV: หน้าฟอร์มและเงื่อนไขนักกีฬาเดิมยังอยู่ครบ
- นำเข้า Excel 2 คนสำหรับรายการเดี่ยวที่รับ 1 คน/ใบสมัคร: แยกเป็น 2 ใบสมัคร และทั้งคู่มีรายชื่อครู
- กรณีใบสมัครถูกส่งคืน: เปิดแก้ไขแล้วเห็นรายชื่อครูทุกคนและสามารถปรับข้อมูลได้
- บัญชีโรงเรียนที่ไม่ได้รับสิทธิ์จัดการโรงเรียนอื่นยังไม่สามารถลงทะเบียนแทนกันได้

## ความเข้ากันได้และข้อจำกัด

Migration 0015 ใช้ **overload 5 argument** ของ RPC `sports_register_individual_batch` โดยคง RPC 4 argument เดิมให้ไคลเอนต์รุ่นเก่าทำงานชั่วคราวขณะ Deploy และตรวจสิทธิ์เดิมภายใน SQL เหมือนเดิม ข้อมูลใบสมัครเก่าไม่ถูกลบหรือเปลี่ยนโดย Migration

ตรวจไวยากรณ์ TypeScript/TSX ด้วย TypeScript parser ครบ 64 ไฟล์ และตรวจโครงสร้างการส่งข้อมูลระหว่างหน้าเว็บกับ SQL แล้ว **ยังไม่ได้รัน Next.js Production Build หรือทดสอบ Supabase จริง** ในสภาพแวดล้อมนี้
