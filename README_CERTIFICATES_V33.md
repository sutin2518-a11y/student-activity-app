## สิ่งที่ V1 ทำได้

- ใช้เมนู **🏅 ระบบออกเกียรติบัตร · V1** ที่เพิ่มบนหน้า `/group-sports` หรือเปิด `/group-sports/certificates`
- ใช้โรงเรียน/รายการแข่งขัน/ทะเบียนนักกีฬา (`sports_events`, `sports_entries`, `sports_athletes`) เดิม ไม่ต้องสร้างโรงเรียนหรือสมัครสมาชิกใหม่
- **กีฬาทั่วไป**: ชนะเลิศ 1, รองชนะเลิศอันดับ 1 จำนวน 1, รองชนะเลิศอันดับ 2 จำนวน **2** (อันดับ 3 ร่วม)
- **กรีฑา**: ชนะเลิศ 1, รองชนะเลิศอันดับ 1 จำนวน 1, รองชนะเลิศอันดับ 2 จำนวน **1** (ไม่มีอันดับ 3 ร่วม) ระดับบุคคลใช้ใบสมัครแยกตามนักกีฬา
- ผู้ดูแลหลักสามารถมอบหมายอีเมล Google ที่ยืนยันตัวตนแล้วให้กรอกผล **เฉพาะรายการ** ที่ได้รับมอบหมาย
- ส่งผล → ผู้ดูแลอนุมัติ → ผู้ดูแลเผยแพร่ → ระบบออกเลขที่และเกียรติบัตรรางวัลอัตโนมัติ
- นักกีฬาทุกคนและครูผู้ควบคุมของทีม/ผู้แข่งขันที่ได้รับรางวัลจะได้รับเกียรติบัตร **รางวัล**
- นักกีฬา **ทุกคนในใบสมัครสถานะ `approved`** และครูผู้ควบคุมที่ลงทะเบียนไว้จะได้รับเกียรติบัตร **เข้าร่วม** เมื่อผู้ดูแลเปิดการออกเอกสารเข้าร่วมของรายการนั้น (ชื่อครูซ้ำจากหลายใบสมัครในรายการเดียวกันจะออกใบเข้าร่วมเพียงใบเดียวต่อโรงเรียน)
- โรงเรียนลงชื่อเข้าใช้ด้วยบัญชีโรงเรียนเดิม พิมพ์ได้ **เฉพาะเอกสารของโรงเรียนตนเอง** เลือกพิมพ์บางใบหรือพิมพ์ทั้งหมดเป็น A4 แนวนอน/Save as PDF
- เลขที่เอกสาร `PG69-00000001` และ QR Code แบบออฟไลน์ (ไม่มีบริการภายนอก) เชื่อมไปหน้า `/group-sports/certificates/verify/<token>` เพื่อตรวจสอบเอกสารผ่านโทเค็นที่เดายาก
- เก็บ snapshot ชื่อ/โรงเรียน/รายการ/อันดับ/ชื่อผู้ลงนามของเอกสารที่ออกแล้ว เพื่อไม่ให้เปลี่ยนตามการแก้ข้อมูลใบสมัครภายหลัง
- V1 **ไม่เขียนทับ** ผลฟุตบอล ตารางแข่งขัน ตารางคะแนน หรือผลกีฬาระบบกลาง

## การติดตั้ง (ต้องทำตามลำดับ)

1. สำรอง/Commit โปรเจกต์เดิมใน GitHub Desktop ก่อน
2. นำ **เฉพาะไฟล์ใน `football-certificates-v33-changed-files.zip`** ไปวางทับโปรเจกต์ v32.2 เดิม (มีเฉพาะไฟล์ใหม่และเมนูที่แก้)
3. เข้า Supabase **SQL Editor** (ฐานข้อมูลเดียวกับกีฬากลุ่ม) สำรองฐานข้อมูลก่อน แล้วรันไฟล์:
   `supabase/migrations/202611230027_sports_certificates_v1.sql`
4. ตรวจว่า SQL ไม่แจ้งข้อผิดพลาด และตรวจสิทธิ์บุคคลทดลองก่อนเผยแพร่จริง
5. เปิด VS Code, รัน `npm install` (ไม่มี dependency ใหม่) แล้ว `npm run build`
6. Commit + Push ด้วย GitHub Desktop → ตรวจ Vercel Deploy ผ่าน → เข้า `/group-sports/certificates`
7. ด้วยบัญชี **ผู้ดูแลหลัก**: เปิดรายการกีฬาที่จะออกใบ → แท็บ **ตั้งค่าระบบ** → ตั้งค่าหัวเกียรติบัตร ชื่อและตำแหน่งผู้ลงนาม **ก่อน** ออกใบใด ๆ
8. เพิ่มอีเมล Google ผู้กรอกผลที่ได้รับมอบหมายเฉพาะรายการ (ถ้าต้องการให้กรรมการกรอกแทนผู้ดูแล)
9. กรรมการ/ผู้ดูแล: แท็บ **บันทึกผล** → เลือกทีม/ใบสมัครอันดับ 1, 2, 3, 3 ร่วม (เฉพาะกีฬาทั่วไป) → **ส่งผล**
10. ผู้ดูแล: แท็บ **อนุมัติ / เผยแพร่** → ตรวจทุกอันดับ → **อนุมัติ** → **เผยแพร่ผลและสร้างเกียรติบัตรรางวัล**
11. หลังแข่งขันจริงและยืนยันรายชื่อผู้เข้าร่วมแล้ว: ผู้ดูแลแท็บ **ตั้งค่า** → **เปิดพิมพ์เกียรติบัตรเข้าร่วม**
12. แต่ละโรงเรียน: เข้าใช้ `/group-sports/login` ด้วย Username/Password เดิม → **เกียรติบัตร V1** → เลือกรายการ → เลือกเอกสาร → พิมพ์ A4 แนวนอนหรือ Save as PDF

**หมายเหตุสำคัญ**: อย่ากดเผยแพร่จนกว่าจะแน่ใจว่าลำดับ 1–3 ถูกต้อง เพราะ V1 ล็อกอันดับหลังเผยแพร่เพื่อป้องกันการออกเกียรติบัตรผิดฉบับ หากจำเป็นต้องแก้ไขผลที่เผยแพร่แล้ว ต้องดำเนินการผ่านผู้ดูแลฐานข้อมูลตามกระบวนการควบคุม ไม่ควรแก้ SQL โดยไม่ตรวจเลขเอกสารและการเพิกถอน

## สิทธิ์ความปลอดภัย

- `competition_admin` หรือ `super_admin` ของการแข่งขัน: บันทึกผล อนุมัติ เผยแพร่ เปิดเข้าร่วม ตั้งค่า มอบหมายกรรมการ พิมพ์ทุกโรงเรียน
- กรรมการที่ถูกมอบหมายเป็นราย event: ลงข้อมูลและส่งผล **ได้เฉพาะรายการตนเอง** โดยต้องลงชื่อผ่าน Google ที่ยืนยันตัวตนแล้ว ไม่ใช่เพียงชื่ออีเมลในฟอร์ม
- `school_manager`: พิมพ์ **เฉพาะใบของโรงเรียนตัวเอง** ที่ออกเอกสาร/เผยแพร่แล้ว โดยใช้บัญชีโรงเรียนเดิม
- บุคคลทั่วไป: **ไม่สามารถเรียกดูทะเบียนนักกีฬา/ผู้รับทั้งหมด** สามารถตรวจสอบเกียรติบัตรผ่าน QR ที่มีโทเค็นเฉพาะเอกสารเท่านั้น
- ไม่มีการให้สิทธิ์อ่าน/เขียนตารางเกียรติบัตรโดยตรงแก่ anonymous หรือ authenticated ใช้ฟังก์ชัน RPC ที่ตรวจสิทธิ์เท่านั้น

## ประเด็นที่ต้องตรวจสอบก่อนใช้งานจริง

- ฐานข้อมูลโรงเรียน/รายการ และใบสมัครมีอยู่จริง ไม่มีฟังก์ชันสร้างใบสมัครแทนทะเบียนนักกีฬา
- สถานะใบสมัครต้องเป็น `approved` (การบันทึกใบสมัครปัจจุบันมี trigger รับข้อมูลอัตโนมัติอยู่แล้ว)
- **การมีชื่ออยู่ในใบสมัครไม่ได้ยืนยันว่าได้ลงแข่งขันจริง**: ผู้ดูแลต้องตรวจรายชื่อกับกรรมการ/การเช็กชื่อหน้างานให้เรียบร้อยก่อนเปิดเกียรติบัตรเข้าร่วม เพราะ V1 ยังไม่มีระบบเช็กชื่อผู้ลงแข่งรายบุคคล
- ระบบออกเกียรติบัตรรางวัลและเข้าร่วมให้คนเดียวกันได้ **สองฉบับคนละประเภท** ตามที่กำหนด
- **ภาพลายเซ็นจริงยังไม่รวมใน V1 นี้**: มีชื่อและตำแหน่งผู้ลงนาม พร้อมเส้นสำหรับเซ็นบนกระดาษ; หากจะออกเอกสารที่มีลายเซ็นดิจิทัลหรือรูปลายเซ็นจริง ต้องติดตั้งช่องเก็บภาพลายเซ็นและขั้นตอนอนุมัติการใช้ภาพอย่างปลอดภัยเพิ่ม
- หากต้องออกเอกสารแทนนักกีฬาที่ไม่ได้ลงทะเบียนในระบบ, ตรวจเข้าร่วมรายบุคคล หรือเชื่อมกับผลส่วนกลางอัตโนมัติ เป็นงานเพิ่มในรุ่นถัดไป
- ก่อนใช้งานจริงทดสอบกับบัญชี 3 กลุ่ม: ผู้ดูแลหลัก, Google กรรมการที่รับมอบหมาย, บัญชีโรงเรียนอย่างน้อย 2 โรงเรียน เพื่อยืนยันว่าโรงเรียน A มองไม่เห็นเอกสารโรงเรียน B
