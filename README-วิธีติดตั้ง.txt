อัปเดตหน้าหลักกีฬากลุ่ม – ตัวกรองประเภทกีฬาในหน้าต่างกำลังแข่งขัน

สิ่งที่ปรับปรุง
1. เพิ่มดรอปดาวน์ “ประเภทกีฬา” ในหน้าต่างกำลังแข่งขัน โดยค่าเริ่มต้นเป็น “ทุกประเภทกีฬา”
2. เลือกกรองได้ 10 ประเภท ได้แก่ E-Sport (RoV), ฟุตบอล, ฟุตซอล, บาสเกตบอล, วอลเลย์บอล, เซปักตะกร้อ, เปตอง, เทเบิลเทนนิส, มวยสากลสมัครเล่น และกรีฑา
3. เมื่อเลือกประเภทกีฬา จะแสดงคู่ที่กำลังดำเนินการทั้งหมดของประเภทนั้น และโปรแกรมถัดไปอีก 3 รายการ โดยรายการด้านขวาเลื่อนได้
4. เมื่อเลือก “ทุกประเภทกีฬา” จะแสดงคู่หลัก 1 คู่ และรายการถัดไปอีก 3 คู่
5. เพิ่มข้อมูลโปรแกรมกรีฑาจาก RPC sports_ath_public แบบอ่านอย่างเดียว โดยไม่ดึงรายชื่อนักเรียนหรือข้อมูลทะเบียน
6. คงการนำทางไปยังหน้ากีฬาที่เกี่ยวข้องเมื่อคลิกรายการ
7. คงแบนเนอร์เวอร์ชันล่าสุดไว้ในชุดอัปเดต เพื่อไม่ให้เส้นทางรูปภาพขาด

วิธีติดตั้ง
1. สำรองโปรเจกต์ปัจจุบัน หรือ Commit งานใน Git ก่อน
2. แตกไฟล์ ZIP นี้
3. คัดลอกโฟลเดอร์ src และ public จาก ZIP ไปวางที่โฟลเดอร์หลักของโปรเจกต์ student-activity-app
4. เมื่อ Windows ถาม ให้เลือก Replace ไฟล์ที่มีชื่อเดียวกัน
5. รัน npm run dev เพื่อตรวจสอบหน้าเว็บ แล้วทดสอบบนมือถือด้วย
6. เมื่อผ่านแล้วจึง Commit และ Push ผ่าน GitHub Desktop เพื่อ Deploy

ความปลอดภัยของระบบลงทะเบียน
- ไม่ได้แก้ไขไฟล์ Registration, SportRegistrationEmbed, ฟอร์มลงทะเบียนนักกีฬา, การอัปโหลดรายชื่อ/รูป, สิทธิ์โรงเรียน หรือกระบวนการอนุมัติ
- ไม่ได้แก้ไขตารางฐานข้อมูล, SQL Migration, RPC สำหรับการลงทะเบียน หรือข้อมูลนักกีฬา
- ไม่มี SQL ที่ต้องนำไปรัน และไม่ต้อง Reset ข้อมูลใด ๆ
- GroupSportsDashboard.tsx เปลี่ยนเฉพาะการอ่านข้อมูลสาธารณะสำหรับหน้าหลัก โดยเพิ่ม RPC sports_ath_public และการ Refresh ของข้อมูลกรีฑาเท่านั้น ส่วน logic ลงทะเบียนคงเดิม

หมายเหตุ
สถานะ LIVE จะแสดงเมื่อฐานข้อมูลของรายการนั้นมีสถานะ live หรือ in_progress อยู่แล้ว ส่วนกีฬาเฉพาะที่มีสถานะเพียง published/scheduled/completed จะแสดงเป็นโปรแกรมถัดไปจนกว่าจะมีสถานะการแข่งขันจริงในระบบ ไม่ได้คาดเดาจากเวลาเริ่มแข่งขัน

การตรวจสอบ
- ตรวจ syntax ของไฟล์ TSX ทั้งสองไฟล์ด้วย TypeScript transpile: ผ่าน
- ยังไม่ได้รัน npm run build ในสภาพแวดล้อมนี้ เนื่องจาก ZIP ต้นฉบับไม่มี node_modules จึงควรทดสอบ npm run dev/build ในเครื่องของผู้พัฒนาก่อน Deploy
