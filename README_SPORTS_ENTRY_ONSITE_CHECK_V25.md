# ระบบกีฬากลุ่ม v25 — รับข้อมูลใบสมัครทันที / ตรวจนักกีฬา ณ สนาม

## ขอบเขต
- ใช้กับ **ใบสมัครทีมและนักกีฬาในเมนู ลงทะเบียน** ทุกประเภทกีฬา รวมถึงการแนบรูปนักกีฬา
- **ไม่มีขั้นตอนกดอนุมัติหรือส่งคืนให้แก้ไขทางออนไลน์**; โรงเรียนส่งใบสมัครสำเร็จถือเป็นการรับข้อมูล และโรงเรียนรับรองความถูกต้องของข้อมูลที่ส่ง
- ฝ่ายจัดการแข่งขันตรวจตัวจริง คุณสมบัติ และเอกสารหลักฐาน ณ สนาม ในวันแข่งขัน
- ยังคงปุ่ม ดูรายชื่อ, แนบรูปใบสมัครเดิม, พิมพ์ใบสมัคร PDF และตัวเลือกกรองตามโรงเรียน/รายการกีฬา
- **ไม่เปลี่ยนขั้นตอนตรวจรับ Word** ในเมนู ส่งข้อมูลโรงเรียน ซึ่งแยกอีกระบบหนึ่ง

## วิธีติดตั้ง (สำคัญ: สำรองข้อมูลก่อน)
1. สำรองตาราง `public.sports_entries` ใน Supabase ก่อน
2. เปิด Supabase SQL Editor รัน `supabase/migrations/202611220020_sports_entries_auto_receive_on_site_check.sql` (ต้องรัน migrations เดิมจนถึง 0019 แล้ว)
3. แตก Patch v25 ลงในโปรเจกต์ v24.1 รักษาโครงสร้างโฟลเดอร์เดิม จากนั้น Commit และ Push
4. ทดสอบบนสภาพแวดล้อมทดสอบแยกฐานข้อมูล หากไม่ได้แยกฐานข้อมูล อย่าทดลองสร้างรายการจำลองในข้อมูลจริง
5. ทดสอบว่าใบสมัครเดิมที่เคยเป็น `submitted` หรือ `rejected` เปลี่ยนเป็น `approved` (ใช้เป็นสถานะ **รับข้อมูลแล้ว** ไม่ได้หมายถึงตรวจผ่าน) และเห็นได้ในการจัดโปรแกรม/ลงผลแข่งขัน
6. ทดสอบลงทะเบียนกีฬาเดี่ยวจาก Excel และ RoV 1 ใบสมัคร รูปถ่ายยังแนบได้, PDF ยังพิมพ์ได้ และไม่มีปุ่มอนุมัติ/ส่งคืน

## หมายเหตุเรื่องข้อมูลเดิม
SQL นี้ทำให้ใบสมัครเก่าที่อยู่ในสถานะ `submitted` และ `rejected` กลายเป็น `approved` เพื่อให้ใช้แผนงานใหม่ได้ทั่วถึง ข้อมูลนักกีฬาและรูปถ่ายไม่ถูกลบ `return_reason` ของรายการเก่ายังเก็บอยู่ในฐานข้อมูลเป็นประวัติ แต่ไม่แสดงข้อความส่งคืนบนหน้าเว็บ

### SQL ตรวจสถานะหลังติดตั้ง
```sql
select status, count(*) from public.sports_entries group by status order by status;
```

### ข้อจำกัดของการตรวจ
ยังไม่ได้เชื่อมทดสอบกับ Supabase Production หรือรัน Next.js Production Build ในสภาพแวดล้อมที่มี dependencies ครบ การตรวจตัวนักกีฬา ณ สนามยังเป็นกระบวนการปฏิบัติงานจริง ไม่ใช่ปุ่มตรวจออนไลน์ใหม่
