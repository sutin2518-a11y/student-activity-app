# Hotfix v33.4 — ศูนย์มอบหมายกรรมการกีฬา และแก้การเข้าสู่ระบบ

ฐานโค้ด: ZIP `ระบบกิจกรรม_แยกพิมพ์เกียรติบัตร_v33.3.zip` ที่ส่งไว้ก่อนหน้า

**คำเตือนสำคัญ:** ภาพที่ผู้ใช้แนบล่าสุดแสดง *Certificates V1.2* แต่โค้ด ZIP ฐานเก่าที่มีอยู่แสดง *Certificates V1.1* ดังนั้น **อย่าวางทับไฟล์ TSX ที่แก้ในระบบ V1.2 โดยไม่ตรวจ diff** เพราะอาจย้อนฟีเจอร์ที่เพิ่งปรับไป ให้ Merge การเปลี่ยนแปลงจากไฟล์ `.patch` หรือส่ง ZIP ปัจจุบันเพื่อให้รวมโค้ดเข้ากับรุ่นล่าสุดอย่างปลอดภัย

## สาเหตุที่พบ

1. หน้าเกียรติบัตรใช้ `sports_certificate_officials`: กรรมการบันทึกผลแยกตาม `event_id`
2. หน้า E-Sport ใช้ `sports_esports_admins`: ผู้ดูแลการแข่งขัน RoV ครอบคลุมชายและหญิงทั้งคู่
3. `/auth/complete` เดิมตรวจ `sports_esports_my_access` แต่ไม่ตรวจสิทธิ์กรรมการเกียรติบัตร ทำให้กรรมการภายนอกที่ได้รับมอบหมายเฉพาะเกียรติบัตรอาจถูกปฏิเสธหรือไม่ถูกนำทางเข้าหน้าจัดการ
4. สาเหตุการเข้าสู่ระบบไม่ได้ของบัญชี E-Sport บางคน **ยังสรุปไม่ได้จากภาพรายชื่อ** ต้องตรวจสถานะ Google/Supabase Auth และข้อความผิดพลาดจริง

## สิ่งที่แก้

- เพิ่ม `/group-sports/certificates/officials` เป็นหน้าจัดการรายชื่อกรรมการจุดเดียวสำหรับ Admin หลัก
- แสดงสิทธิ์สองช่องแยกกัน: (ก) บันทึกผลเกียรติบัตรรายการที่เลือก (ข) ดูแล RoV ชาย/หญิง
- เพิ่มแบบฟอร์มมอบหมาย `certificate`, `esports` หรือ `both` (เฉพาะ RoV); สั่งเปลี่ยนสิทธิ์ผ่าน RPC ที่ตรวจ Principal Admin และทำงานแบบธุรกรรมเดียว
- ใช้รายชื่อ Union จากตารางเดิมสองตาราง ไม่ย้าย ไม่ลบ ไม่เปิดสิทธิ์ข้ามตารางให้อัตโนมัติ
- เพิ่มสถานะบัญชี Google: `ready`, `not_signed_in`, `unconfirmed_email`, `not_google` เพื่อช่วยตรวจว่าทำไมล็อกอินแล้วไม่พบสิทธิ์
- เปลี่ยนปุ่มมอบหมายในหน้าเกียรติบัตรและหน้า E-Sport เป็นลิงก์ไปหน้าจัดการกลาง
- ปรับ `/auth/complete` ให้รับรู้กรรมการเกียรติบัตร และยอมให้บัญชีที่ได้สิทธิ์เฉพาะกีฬาเข้าใช้งานได้โดยไม่ต้องมีโปรไฟล์ครูโรงเรียนเชียงคำฯ
- หากยังไม่ได้ติดตั้ง RPC ใหม่ ระบบเข้าสู่ระบบของบัญชีเดิมไม่ถูกล็อกเพราะ RPC ที่ยังไม่มี (แต่ต้องติดตั้ง SQL เพื่อใช้ฟีเจอร์ใหม่)

## ขั้นตอนติดตั้ง

1. สำรองโค้ดด้วย Git และสำรองฐานข้อมูลตามกระบวนการของโรงเรียน
2. เปรียบเทียบ/รวม patch กับโค้ดล่าสุดก่อน Deploy โดยเฉพาะไฟล์ `CertificatesDashboard.tsx`, `GroupSportsDashboard.tsx`, `esports/page.tsx`, `auth/complete/page.tsx`
3. ใน Supabase SQL Editor รัน **`supabase/migrations/202611240028_sports_officials_unified_access.sql`** หลัง migrations 0025 และ 0027; SQL นี้ไม่ลบหรือแก้ข้อมูลผลแข่งขันหรือเกียรติบัตรเก่า
4. รัน `npm run build` จากโปรเจกต์ที่ติดตั้ง dependencies แล้ว จากนั้น Commit/Push ขึ้น Vercel
5. Admin หลักเปิด `/group-sports/certificates/officials` ทดสอบรายชื่อ RoV 1 รายการ; ต้องเห็นรายชื่อทั้งสองกลุ่มพร้อมป้ายแยกหน้าที่
6. ทดลองเพิ่มบัญชี **ทดสอบ** หนึ่งบัญชีใน scope `certificate` เท่านั้น ตรวจว่าไม่สามารถแก้คู่แข่งขัน RoV; จากนั้นเพิ่ม scope `esports` และตรวจว่าจัดการ RoV ได้
7. ให้ผู้ใช้เปิด `/login` เข้าด้วย Google อีเมลตรงกับที่มอบหมาย; ถ้าไม่มีบัญชี Google ที่ยืนยันแล้วต้องตรวจ Google OAuth/Supabase ก่อน
8. ทดสอบบัญชีโรงเรียนปกติว่ายังพิมพ์เกียรติบัตรของตนเองได้ และไม่สามารถเข้าหน้ามอบหมายกรรมการโดยตรง

## ขอบเขตที่ยังไม่ได้ยืนยัน

- การ Build บน Vercel และสิทธิ์ OAuth ของบัญชีจริง เพราะไม่มีการเชื่อม Supabase/Vercel production ในสภาพแวดล้อมนี้
- รายชื่อใน V1.2 online อาจต่างจากฐานเก่าที่ใช้สร้าง Hotfix; ไม่ควรใช้ ZIP เต็มรุ่นเก่าวางทับโดยตรง
- หากรายการแสดงว่า `ready` แต่ยังเข้าระบบไม่ได้ ให้ตรวจ error ที่หน้าล็อกอินและ configuration ของ Google OAuth Redirect URL / Workspace OAuth restrictions; ป้าย ready ยืนยันเฉพาะข้อมูล Google identity และ email confirmation ที่ Supabase มี
