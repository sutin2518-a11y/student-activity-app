CKW v33.31.1 — Athletics Management & Smart Call Room
ติดตั้งต่อจาก v33.30 และ SQL 046 (สำรองไฟล์และฐานข้อมูลก่อนทุกครั้ง)
1. หยุด npm run dev ด้วย Ctrl+C แล้วแตก ZIP วางไฟล์ในราก student-activity-app
   ไฟล์ร่วม GroupSportsDashboard.tsx และ officials/my/page.tsx อ้างอิงจากแพตช์ v33.30;
   หากแก้ไขเพิ่มเติมเอง ให้ merge เฉพาะลิงก์และตัวป้องกันบันทึกผลโดยตรงก่อน Replace.
2. รัน supabase/migrations/202611240047_sports_athletics_v33_31.sql ทั้งไฟล์.
   ใช้เฉพาะเมื่อ SQL 047 เดิมยังไม่ผ่าน และยืนยันว่าโปรแกรมกรีฑาเดิมทั้งหมดเป็น TEST.
   SQL ลบเฉพาะโปรแกรมกรีฑา GS3-AT ของการแข่งขันปี 2569 แล้วสร้าง 84 ช่วงใหม่ใน transaction เดียว.
   ไม่ลบใบสมัคร ผลรางวัล หรือรายการกีฬาอื่น; หากพบระบบรายงานตัวติดตั้งแล้วจะหยุด. ห้ามรันซ้ำหลังสำเร็จ.
3. รัน diagnostics/202611240047_check_athletics.sql (อ่านอย่างเดียว).
   คาดหวัง 84 ช่วง, 54 รายการ, 30 รอบคัดเลือก, 54 รอบชิง, 84 รายงานตัวก่อนแข่ง 30 นาที.
4. npm run build แล้ว npm run dev. เปิด http://localhost:3000/group-sports/athletics
5. แม่แอดมินตรวจตารางและเผยแพร่ฉบับร่างที่กรอง. เปิดรับสมัครในระบบกลางตามเดิม.
   รายการ 109 เปลี่ยนเป็นรอบชิงตามผู้จัด (PDF ต้นฉบับยังคงเดิม). รหัสเก่า GS3-AT-010 และ GS3-AT-014 ไม่มีในฉบับแก้ไข;
   คงรหัส/ใบสมัครเดิมไว้ ไม่สร้างรอบหรือโอนใบสมัครโดยพลการ. ตรวจสอบก่อนเปิดรับสมัคร.
6. มอบหมายกรรมการที่ระบบกลาง /group-sports/officials จากนั้นหน้าใหม่แท็บมอบหมายหน้าที่
   เลือก Call หรือ Field หรือ Both ให้แต่ละคนตามรายการ. สิทธิ์ตรวจจากบัญชีจริงใน SQL.
   สิทธิ์ประกาศรางวัลยังใช้ระบบกลาง sports_cert_can_record แยกจากสิทธิ์จุดรายงานตัว/สนาม.
7. เมื่อรับสมัครครบแล้ว ให้แม่แอดมินจัดรายชื่อจากทะเบียนที่อนุมัติแล้ว (เดี่ยว 1 คน / ผลัด 4 คน).
   การกดยืนยันจัดรายชื่อจะล็อกทะเบียนของรายการนี้ ไม่ให้แก้ไขหรือลบโดยฟังก์ชันทั่วไปหลังจากนั้น
   และปิดรับสมัครถ้าอยู่สถานะ registration. ตรวจทุกชื่อก่อนกด. ไม่รองรับเปิดล็อก/Reset ในรุ่นนี้.
   จากนั้นโรงเรียนพิมพ์ใบรายงานตัวของตนเอง; กรรมการที่มีสิทธิ์พิมพ์ทั้งรายการได้.
8. แท็บพิมพ์: เลือกรายการและรอบ, ค้นโรงเรียน/ชื่อ, เลือกคนหรือทีม, เลือกใบรายงานตัว/บัญชีกรรมการ,
   พิมพ์ A4 แนวนอน 2 ใบต่อหน้า หรือ Save as PDF. รูปถ่ายใช้ private bucket เดิม หากแนบไว้.
   QR มีเฉพาะ UUID ใบรายงานตัว ใช้เครื่องสแกนที่ส่งข้อความเข้า search หรือพิมพ์รหัสเอง.
   ไม่มีสแกนกล้องในตัว ไม่บรรจุข้อมูลนักเรียนไว้ใน QR. พิมพ์ซ้ำหลังจัดช่องวิ่งได้.
9. กรรมการ Call เปิดเรียก, ติ๊กตรวจตัวนักกีฬาทุกคน, ระบุสถานะ/Heat/ช่องหรือลำดับ,
   ปิดรับรายงานตัวหลังตรวจครบ. ไม่มา=DNS. จอประกาศอัปเดตทุก 15 วินาที (polling).
10. Field ยืนยันรับนักกีฬาเข้าสนามทีละใบ, บันทึกเวลาเป็นวินาทีหรือระยะดีที่สุดเป็นเมตร,
    รองรับ OK/DNS/DNF/DQ/NM ตามประเภท. หากคัดเลือก ให้ยืนยันรายชื่อผู้ผ่านรอบตามกติกาจริง
    แล้วปิดผล; รอบชิงดึงเฉพาะผู้ผ่านรอบ. หากชิงโดยตรงดึงใบสมัครเดิม.
11. รอบชิงคำนวณอันดับจากเวลา/ระยะ; ถ้าผลที่กระทบอันดับรางวัลเท่ากันหรือมีผล OK น้อยกว่า 3
    จะไม่ให้เผยแพร่รางวัลอัตโนมัติ. กรรมการที่มีสิทธิ์ประกาศยืนยันอันดับจากหน้าสนาม
    หรือเมนูเกียรติบัตรเดิม. RPC เดิมทำธุรกรรมผล/เหรียญ/เกียรติบัตรพร้อมกัน.
    เก็บอันดับ 1–3 ในตารางกลางเพื่อให้ตรวจ receipt ได้; แสดงอันดับอื่นในหน้ากรีฑาแยก.

ข้อจำกัดสำคัญ
- PDF มีเฉพาะโปรแกรม ไม่ใช่ระเบียบกรีฑาฉบับเต็ม: ยังไม่กำหนดโควตาลงแข่งขันต่อโรงเรียน,
  เกณฑ์เข้ารอบ จำนวนลู่/จำนวน Heat จำนวนครั้งวัดระยะ นักกีฬาสำรองผลัดและเกณฑ์ตัดสินสถิติเท่ากัน.
  ใช้จำนวนผู้วิ่งผลัดจริง 4 คน; ไม่รองรับทีมมีสำรองในรอบรายงานตัวนี้. ทะเบียนไม่ลดเพดานเดิม.
  เก็บระยะดีที่สุดตามใบกรรมการ ยังไม่มีบันทึกแต่ละครั้ง/ตัดสิน tie-break อัตโนมัติ.
- ข้อมูลรายบุคคล/รูป/รหัสใบรายงานตัวอยู่เฉพาะผู้มีสิทธิ์ ไม่แสดงบนจอประกาศสาธารณะ.
- การแก้ผลหลังล็อก/หลังประกาศ และ Reset ข้อมูลกรีฑาจริง ยังไม่รองรับ. ห้ามใช้ Reset เดิมกับข้อมูลกรีฑาที่จัดรายชื่อแล้ว.
- ระบบไม่เพิ่มคู่หรือเวลาใหม่เอง; เก็บโปรแกรม 84 ช่วงตาม PDF พร้อมแก้รอบรายการ 109 ตามผู้จัด. รายการที่เวลาเดียวกันของลู่และลานคงไว้.
- ใช้ไฟล์เดิม v33.30 เป็นฐาน ไม่ได้เข้าถึงฐานข้อมูลจริงหรือเครื่องผู้ใช้.
  ทดสอบข้อมูล/โครงสร้าง 7 ข้อและ Syntax TSX 4 ไฟล์แล้ว; ยังไม่ได้ Production Build หรือรัน PostgreSQL/Supabase จริง.
  ต้องทดสอบสิทธิ์แยกบัญชีและพิมพ์เอกสารจริงจากเครื่องผู้ใช้ ก่อนวันแข่งขัน.
