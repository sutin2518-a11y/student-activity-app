# ระบบกีฬากลุ่ม — เปิดรับสมัครหลายรายการพร้อมกัน (v12)

ต่อยอดจาก v11 โดยคงบัญชีโรงเรียน, รหัสผ่าน 8 ตัว, การลงทะเบียนและตารางแข่งขันเดิม

## ความแตกต่างของสองสถานะ

- `sports_events.status = 'registration'` หมายถึงเปิดรับสมัครนักกีฬาในรายการนั้น
- `sports_schedule_sessions.status = 'published'` หมายถึงเผยแพร่วัน เวลา และคู่แข่งขัน ไม่ใช่การเปิดรับสมัคร

## วิธีติดตั้ง

1. ใช้ Patch v12 ทับโครงการ v11 โดยคงโครงสร้าง `src/...` และ `supabase/...`
2. ใน Supabase SQL Editor ให้รัน `supabase/migrations/202611220014_sports_bulk_registration.sql` หลังจากติดตั้ง migrations จนถึง 0013 แล้ว
3. Commit และ Push ไปยัง GitHub / Deploy Vercel Preview จากนั้นตรวจสอบการแสดงผลด้วยบัญชี Admin
4. เข้าเมนู **จัดการ / ดูโปรแกรม → รายการแข่งขัน** แล้วเลือกเฉพาะรายการที่ตรวจสอบกติกา/รุ่น/เพศ/ชื่อ/รหัสรายการแล้ว
5. ใช้ช่องตัวกรองชนิดกีฬาเพื่อจำกัดกลุ่มที่ต้องการ หรือเลือกทีละแถว จากนั้นกด **เปิดรับสมัครที่เลือก** และยืนยัน
6. ทดสอบด้วยบัญชีโรงเรียน `school_manager` ว่ารายการที่เปิดปรากฏในหน้าลงทะเบียน และโรงเรียนอื่นถูกจำกัดสิทธิ์ตามเดิม

## ระบบสิทธิ์

- ปุ่มเปิดรับสมัครหลายรายการแสดงเฉพาะผู้ที่ผ่านฟังก์ชัน `sports_stage3_admin`
- RPC ใหม่ตรวจว่าบัญชีล็อกอินมี role `competition_admin` ในการแข่งขันนี้ หรือ `super_admin` ที่ตรงขอบเขต
- บัญชีโรงเรียน `school_manager` ไม่มีสิทธิ์เปิดรับสมัคร และห้ามยกระดับเป็น Admin เพื่อแก้ปัญหาเมนูไม่แสดง
- RPC เป็นธุรกรรมเดียว หากรายการใดไม่ผ่านการตรวจ ทุกการเปลี่ยนสถานะของชุดนั้นจะไม่ถูกบันทึก
- จำกัด 1–500 รายการ/ครั้ง และยอมรับเฉพาะสถานะ `draft`, `scheduled`, `closed` พร้อมชื่อและรหัสรายการที่ไม่ว่าง
- บันทึกเหตุการณ์เปลี่ยนสถานะใน `sports_audit_logs`

## หมายเหตุการตรวจสอบ

- `npm run build` ยังไม่ได้ทดสอบในสภาพแวดล้อมนี้ เพราะไม่มีชุด `node_modules` แต่ได้ตรวจการแปลงไวยากรณ์ TypeScript/TSX ของไฟล์ทั้งโครงการ
- ยังไม่ได้ทดลองรัน SQL กับ Supabase จริงหรือทดสอบบทบาทจากบัญชีจริง ต้องทดสอบใน Preview/สภาพแวดล้อมที่เหมาะสมก่อน Production
- การเปิดรับสมัครเป็นการเปลี่ยนสิทธิ์ลงทะเบียนทันที ควรตรวจชื่อกีฬา รุ่น และคุณสมบัติให้เรียบร้อยก่อนเลือกเปิดทั้งหมด
