CKW v33.36 – Volleyball official registration

1. สำรอง Git และฐานข้อมูลก่อนติดตั้ง (ห้ามรีเซ็ตข้อมูลจริง)
2. แตก ZIP แล้วคัดลอกเฉพาะ apply-v33.36.cjs ไปที่ root ของ student-activity-app
3. หยุด dev server แล้วรัน node apply-v33.36.cjs
4. หากขึ้น STOP ห้ามฝืน ให้ส่งข้อความกลับเพื่อตรวจโค้ดจริง
5. npm run build; หากผ่านจึงทดสอบ SQL ใน Supabase โปรเจกต์ทดสอบก่อน (migration 050)
6. SQL ใช้ transaction เพิ่ม 2 ตารางส่วนตัวและ 2 RPC ใหม่ ไม่ปรับ RPC เดิมของกีฬาอื่น ไม่แก้ข้อมูลเดิมตอนติดตั้ง
7. npm run dev และเปิด /group-sports/volleyball?tab=registration
8. ทดสอบด้วยบัญชีที่มีสิทธิ์และข้อมูลทดสอบในฐานทดสอบเท่านั้น: ลงทะเบียน, Excel, เปิดใบสมัคร, พิมพ์ A4; ตรวจสิทธิ์ข้ามโรงเรียน
9. ก่อน Deploy จริง ตรวจ migration 050, Next.js security update และทดสอบครบวงจร

ข้อสังเกต: ฟอร์มหน้าเว็บ 6–12 คน (ตามข้อกำหนดเดิมและขั้นต่ำผู้เล่น 6 คน); แบบพิมพ์คงช่องว่าง 14 แถวตามต้นฉบับ แต่ลงทะเบียนได้ไม่เกิน 12 คน; ไม่มีอัปโหลดรูปหรือสำเนาบัตรประชาชน. คอลัมน์วันที่ Excel แยกวัน/เดือนภาษาไทย/ปี พ.ศ. ใบสมัครเก่าที่ไม่ได้เก็บรายละเอียดเหล่านี้จะแสดงช่องว่างและคำเตือน สามารถให้ Admin แก้ไขในช่วงเปิดรับสมัคร; ไม่เติมค่าปลอม. ไม่เพิ่มช่องลายมือชื่อในแบบพิมพ์เพราะไม่มีในภาพต้นฉบับ แต่ระเบียบกำหนดให้ยื่นรายชื่อพร้อมลายมือชื่อ โปรดให้ผู้จัดยืนยันวิธีลงนาม.

ผลทดสอบ: ติดตั้งกับสำเนาโค้ดและติดตั้งซ้ำผ่าน, transpile syntax 5 TS/TSX ผ่าน, ทดสอบวันที่/จำนวน/ชื่อ/หมายเลขซ้ำผ่าน 8 กรณี. ยังไม่ผ่านการยืนยัน full production build, Excel จริง, SQL runtime, RLS และพิมพ์จริง. SQL ใหม่สมมติ sports_athletes.id เป็น UUID; foreign key จะทำให้ migration หยุดและ rollback หากไม่ตรง.
