CKW v33.26 — Volleyball Management (PHAYAO GAMES)
=================================================
ฐาน: ZIP โปรเจกต์เครื่องบ้าน + ชุดอัปเดต v33.22 ถึง v33.25 ที่ส่งในแชท

ติดตั้ง
1. สำรองโค้ดและฐานข้อมูลจริงก่อน หยุด npm run dev ด้วย Ctrl+C
2. แตก ZIP ลงโฟลเดอร์ที่มี package.json ตรวจ diff ของไฟล์ร่วมก่อน Replace
3. ติดตั้ง Migration 042 ใน Supabase SQL Editor ทั้งไฟล์ หลัง 041 สำเร็จแล้ว
4. รัน diagnostics/202611240042_check_volleyball.sql (อ่านอย่างเดียว)
   คาดหวัง GS3-VB-15F=25, GS3-VB-15M=15, GS3-VB-OF=22, GS3-VB-OM=31 รวม 93
5. npm run build; หากผ่าน npm run dev แล้วเปิด http://localhost:3000/group-sports/volleyball
6. ตรวจด้วยแม่แอดมินก่อนเผยแพร่โปรแกรม; เปิดรับสมัครเมื่อพร้อม
7. ทดสอบกรรมการและบัญชีที่ไม่ได้รับมอบหมาย, ผลรวม, ตารางคะแนน, รางวัล, เอกสาร และ regression ของกีฬาเดิมก่อน Push

ข้อมูลต้นฉบับ
- 4 รุ่น 51 ทีม 14 สาย 93 คู่จาก PDF 8 หน้า
- ทีมหญิงรอบแบ่งกลุ่ม/8 ทีมที่เชียงคำวิทยาคม; ทีมชายรอบแรก/8 ทีมที่ภูซางวิทยาคม
- สนามรอบรองและชิง 12 คู่ในหน้า 5 ไม่ระบุชัด จึงเว้นสนามไว้ให้ยืนยัน
- คู่ชายเกิน 15 ปี หมายเลข 18: ค.ค ตาม PDF เสนอ ดงเจนวิทยาคม ตามสาย D และคู่ที่ขาด
- พ.ป เป็นคำย่อกำกวม ตีความตามสายและความครบถ้วนของคู่พบกันหมด: พินิตประสาธน์ใน 15F/OM, พะเยาประสาธน์วิทย์ใน OF; ให้ยืนยันกับผู้จัด
- เก็บเลขคู่แยกตาม event_id, ไม่เปลี่ยนเวลาแข่งขัน
- ข้อมูลชื่อเต็มตรวจเทียบกับ CSV 21 โรงเรียนที่ผู้ใช้ส่งล่าสุดก่อนเพิ่มประชาบำรุง ไม่ได้อ่านฐานข้อมูลจริง
- ไม่ลบโปรแกรมเดิมหรือเผยแพร่อัตโนมัติ; Migration หยุดหากพบคู่ทั่วไปเดิมหรือจับคู่ชื่อไม่ได้
- ตารางคะแนน ชนะ 2 แพ้ 1 ไม่แข่งขัน 0; กรณีแต้มสะสมเท่ากันให้กรรมการยืนยันผู้เข้ารอบตามกติกาที่ผู้จัดกำหนด
- คะแนนเซตใช้ 25 แต้ม และเซตตัดสิน 15 แต้ม ชนะห่าง 2 แต้ม ตามการตีความกติกา FIVB; PDF ไม่ระบุแต้มรายเซตไว้ตรงๆ จึงต้องยืนยันก่อนใช้จริง
- สมมติใช้ทองแดงร่วม 2 ทีมตามโครงสร้างระบบเดิม PDF ไม่ระบุจำนวนทีมชัด ต้องยืนยันก่อนเผยแพร่

ขอบเขตและข้อจำกัด
- ใช้ sports_football_matches และ group_teams ร่วมกับระบบกีฬาเดิม แต่แยก event_id; volleyball_sets เก็บคะแนนรายเซต
- แม่แอดมินตรวจโปรแกรม และกรรมการที่ได้รับมอบหมายบันทึกผลผ่าน RPC; ใช้ optimistic lock, audit trigger เดิม, จำกัดการแก้ผลหลังรอบถัดไป
- หน้าลงทะเบียนและรูปภาพยังใช้ระบบกลางเดิม (SQL ตรวจนักกีฬา 6–12 คน, เจ้าหน้าที่ 1–3 คน, โรงเรียนในสาย, ใบสมัครซ้ำ และชื่อ/รหัสซ้ำในโรงเรียนผ่าน RPC หลัก) จำนวนขั้นต่ำ 6 คนอิงข้อกำหนดผู้เล่นในสนาม ไม่ใช่จำนวนขั้นต่ำสมัครที่ PDF ระบุโดยตรง
- ยังไม่ได้สร้างฟอร์มเฉพาะที่มีวันเกิด น้ำหนัก ส่วนสูง หมายเลขเสื้อ สีชุด และใบยืนยันแบบหน้า 8; มี PDF ต้นฉบับให้เปิดใช้แทน
- ยังไม่ครอบคลุมการไม่แข่งขันทั้งสองทีม, การประท้วง, การลงโทษ, การตรวจคุณสมบัติอายุและหลักฐานอัตโนมัติ, การแก้คู่รอบแรกกรณีชื่อที่ตีความผิด (ให้แจ้งผู้พัฒนาเพื่อปรับ seed หลังยืนยัน), การตรวจเวลาซ้อนตามระยะเวลาจริง (มีเพียงเวลาเริ่มใน PDF), และการตรวจสิทธิ์ผ่านเส้นทาง admin เดิมทั้งหมด
- อันดับแนะนำและการประกาศครั้งแรกใช้ระบบรางวัลเดิม พร้อมตรวจผลรอบรอง/ชิง; การแก้รางวัลหลังประกาศยังใช้กระบวนการ Admin เดิม ต้องตรวจความตรงกันกับผลรายคู่ด้วยตนเอง
- ไม่รวม Full System Test Mode v33.23; localhost เชื่อม Supabase จริง ไม่ควรทดลองบันทึกคะแนนจริงถ้าไม่ได้รับอนุญาต

ผลตรวจในเครื่องจัดทำไฟล์: ชุดทดสอบ 7/7 ผ่าน; TypeScript transpile syntax ตรวจเฉพาะไฟล์ TS/TSX ใน patch ไม่ใช่ full type-check. ยังไม่ได้รัน SQL กับ PostgreSQL/Supabase หรือ npm run build จริง เนื่องจากไม่มีสภาพแวดล้อมฐานข้อมูลจริงและ dependencies ทั้งโปรเจกต์
