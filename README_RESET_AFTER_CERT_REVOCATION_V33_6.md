# PHULANGKA GAMES 2569 — Hotfix v33.6
## แก้ปัญหา: ยกเลิกเกียรติบัตรแล้ว แต่ยังลบใบสมัครไม่ได้

**ฐาน:** โปรเจกต์ v33.5 (รวมฟีเจอร์ยกเลิกและออกเกียรติบัตรใหม่, ระบบรีเซต v33.4)

### สาเหตุ

- RPC `sports_admin_reset` v33.4 นับ `sports_certificates_issued` **ทุกสถานะ** เป็นเอกสารที่ห้ามลบ แม้ `revoked_at` จะไม่เป็น NULL แล้ว
- `sports_certificates_issued.entry_id` เดิมเป็น `NOT NULL` และมี Foreign Key `ON DELETE RESTRICT` ทำให้ลบใบสมัครที่อ้างถึงเกียรติบัตรยกเลิกแล้วไม่ได้
- หากมีคะแนน/ผลการแข่งขันจริงหรือรายการจัดอันดับที่อ้างใบสมัครนั้น การลบใบสมัครรายเดียวจะถูกป้องกันด้วยอีกเงื่อนไขหนึ่ง

### สิ่งที่แก้

1. แสดงจำนวนเกียรติบัตรที่ **ยังไม่ได้ยกเลิก** แยกจาก **ยกเลิกแล้ว** ในหน้า `/group-sports/reset`
2. ตรวจเฉพาะเกียรติบัตรของ **ใบสมัครที่เลือก** เมื่อสั่งลบใบสมัครเดียว ไม่เอาเอกสารโรงเรียนอื่นในรุ่นเดียวกันมาบล็อก
3. ไม่อนุญาตลบหากมีเกียรติบัตร `revoked_at IS NULL` ไม่ว่าสถานะจะใช้งานอยู่หรือปิดใช้งานชั่วคราว (inactive)
4. เมื่อยกเลิกเกียรติบัตรทุกฉบับของเป้าหมายแล้ว สามารถรีเซตได้ **ถ้าไม่มีผลแข่งขัน/อันดับที่ขัดข้อง** และยังไม่ถึงวันที่ปิดรีเซต
5. เปลี่ยน FK ของเอกสารเกียรติบัตรเป็น `ON DELETE SET NULL` เพื่อรักษาเลขที่, QR, ผู้รับ, ประวัติการยกเลิก และเหตุผลไว้ แม้ใบสมัครทดสอบถูกลบ
6. เพิ่ม Trigger ห้ามลบใบสมัครที่ยังมีเกียรติบัตรไม่ยกเลิก แม้มีช่องทางอื่นเรียกคำสั่งลบ
7. ห้ามออกเกียรติบัตรฉบับใหม่แทนเอกสารที่ใบสมัครต้นทางถูกรีเซตไปแล้ว
8. ไม่เปลี่ยนบัญชีโรงเรียน, รายการกีฬา, คู่แข่งขันต้นฉบับ, โปรแกรม, สิทธิ์กรรมการ, หรือรูปภาพใน Storage ระหว่างติดตั้ง

### ติดตั้ง (จำเป็นต้องทำตามลำดับ)

1. สำรอง Supabase **Database และ Storage** และ Commit งานบน Git ก่อน
2. ตรวจว่ารัน Migration `202611230028_sports_safe_admin_reset.sql` (v33.4) และ `202611230029_sports_certificate_revocation_reissue.sql` (v33.5) แล้ว
3. ใน Supabase SQL Editor รันไฟล์ **`supabase/migrations/202611230030_sports_reset_revoked_certificates_v33_6.sql`** (ครั้งเดียว; การรันไฟล์นี้ยังไม่ลบข้อมูล)
4. คัดลอกไฟล์ `src/components/group-sports/SportsResetManager.tsx` จาก ZIP ลงโปรเจกต์เดิม
5. รัน `npm run build` จากเครื่องที่มี dependencies แล้ว Commit + Push เพื่อ Deploy Vercel
6. เข้าด้วย **Admin หลัก** ไปที่ `/group-sports/reset` กด **ตรวจสอบจำนวนข้อมูลก่อนลบ** และตรวจจำนวนแยกสองประเภท
7. ถ้าเอกสารยังไม่ได้ยกเลิก > 0 ให้กลับไปจัดการเอกสารทุกฉบับที่เกี่ยวข้อง รวมถึงฉบับ **ปิดใช้งานชั่วคราว** ซึ่งยังไม่ใช่การยกเลิก
8. ถ้าเหลือแต่ฉบับยกเลิกแล้ว และไม่มีผลแข่งขัน/อันดับที่เกี่ยวข้อง ระบบจะเปิดให้พิมพ์ยืนยัน `ลบข้อมูลทดสอบ 2569` แล้วรีเซตได้
9. หากมีผลแข่งขันหรืออันดับ ให้พิจารณา **รีเซตประเภทการแข่งขัน** (แต่ต้องยกเลิกเกียรติบัตรที่ยังไม่ยกเลิกทุกฉบับของรายการนั้นก่อน)
10. หลังรีเซตให้ตรวจใบสมัครหายจากทะเบียนจริง และทดสอบสแกน QR ของเกียรติบัตรที่ยกเลิกว่าขึ้นสถานะ **ยกเลิกแล้ว**

### ข้อจำกัดด้านความปลอดภัยที่ยังคงเดิม

- Admin หลักเท่านั้น
- เปิดให้รีเซตก่อน **30 พฤศจิกายน 2569 เวลาไทย** เท่านั้น
- ยังต้องตรวจจำนวนและ fingerprint, พิมพ์ข้อความยืนยันก่อนลบ
- Archived snapshot อยู่ใน `sports_admin_reset_archives` และรูปภาพต้องสำรอง/ลบจาก Storage แยกต่างหาก
- ยังไม่มีการกู้คืน Archive อัตโนมัติ
- อย่ารัน `DELETE` หรือ `TRUNCATE` ด้วยตนเองใน SQL Editor

### ข้อควรทราบ

เกียรติบัตรที่แสดง **ปิดใช้งานชั่วคราว** ไม่ได้ถูกยกเลิก และยังต้องกด **ยกเลิกเกียรติบัตร** ก่อนถ้าต้องการลบใบสมัคร/รีเซตรายการนั้น

**สถานะทดสอบ:** ตรวจโครงสร้าง SQL และไวยากรณ์ TSX แล้ว แต่ยังไม่ได้รัน Migration หรือทดสอบกับฐานข้อมูล Production และไม่ได้ยืนยัน `npm run build` ของ Next.js ในสภาพแวดล้อมนี้
